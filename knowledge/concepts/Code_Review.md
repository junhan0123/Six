# 代码审查规范

## 审查维度

### 正确性
- 逻辑是否正确
- 边界条件是否处理
- 异常是否捕获

### 可读性
- 命名是否清晰
- 注释是否必要
- 结构是否合理

### 性能
- 是否有明显性能问题
- 是否有内存泄漏风险
- 是否有不必要的计算

### 安全性
- 是否有注入风险
- 是否有敏感信息泄露
- 是否有权限问题

### 可维护性
- 是否易于扩展
- 是否有重复代码
- 是否过度设计

## 审查流程

1. 读取修改的文件
2. 对照成功标准
3. 逐项检查
4. 记录问题
5. 给出建议

## 输出格式

```
## 审查结果
- 通过：...
- 警告：...
- 错误：...

## 建议
1. ...
2. ...
```
