# AI 记忆架构三层模型

> **归档日期：** 2026-08-11
> **来源：** 用户提供的架构图
> **标签：** #AI记忆 #记忆架构 #Agent #ContextWindow #VectorDB

## 概述

AI Agent 的记忆系统可分为三层，每层对应不同的技术实现和用途。

## 三层架构

### 1. 短期记忆（Working Memory）

- **机制：** 保留最近 N 轮对话，直接放入 Prompt
- **技术：** Context Window + List 结构
- **作用：** 保持当前语境连贯
- **示例：** 当前对话的历史消息

### 2. 实体/画像记忆（Entity Memory）

- **机制：** 提取明确的事实信息，存入 KV 库或图谱
- **技术：** JSON/SQL + 知识图谱
- **作用：** 存储结构化事实
- **示例：** 用户偏好、项目信息、关系数据

### 3. 长期情景记忆（Episodic Memory）

- **机制：** 历史对话切片向量化，进行语义检索
- **技术：** Vector DB + Embedding
- **作用：** 模糊语义召回
- **示例：** "上次那个 XX 项目做了什么？"

## 与 Hermes 的对应关系

| 层 | 当前实现 | 状态 |
|---|---------|------|
| 短期记忆 | 对话上下文（session context） | ✅ 已有 |
| 实体记忆 | memory 工具 + Obsidian 知识库 | ✅ 已有 |
| 情景记忆 | session_search（FTS5 文本检索） | ⚠️ 可用向量检索增强 |

## 与小6项目的关联

小6项目如果要做持久化 AI 记忆，可直接套用此模型：

1. **短期记忆** — 对话上下文管理（Context Window 优化）
2. **实体记忆** — 用户画像、项目信息、能力模块状态（JSON/SQL）
3. **情景记忆** — 历史对话向量化检索（Embedding + Vector DB）

## 技术选型建议

| 层 | 推荐方案 | 说明 |
|---|---------|------|
| 短期记忆 | 已有（上下文窗口） | 优化压缩策略即可 |
| 实体记忆 | SQLite + JSON | 轻量、可靠、易维护 |
| 情景记忆 | ChromaDB / Qdrant | 向量检索，替代 FTS5 |
