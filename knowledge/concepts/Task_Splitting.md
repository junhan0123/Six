# 任务拆分规范

## 拆分原则

1. 每个子任务必须是独立的、可执行的
2. 子任务之间尽量减少依赖
3. 每个子任务有明确的完成标准
4. 子任务粒度适中（不宜过大或过小）

## 拆分模板

### 目标层

一句话描述最终目标。

### 阶段层

将目标拆分为 2-5 个阶段，每个阶段有明确产出。

### 任务层

每个阶段拆分为 2-5 个任务，每个任务有明确动作。

### 动作层

每个任务拆分为具体可执行的动作（工具调用）。

## 拆分示例

```
目标：搭建一个静态网站

阶段一：环境准备
  任务1.1：检查开发环境
  任务1.2：安装必要工具

阶段二：内容创建
  任务2.1：创建页面结构
  任务2.2：编写页面内容

阶段三：测试部署
  任务3.1：本地测试
  任务3.2：部署上线
```

## 注意事项

- 不要一次性拆分超过 20 个子任务
- 复杂任务可以分多次拆分
- 拆分过程中发现新任务及时补充
- 拆分完成后等待确认再执行
