# 自动代码开发工作流

## 核心流程

需求分析 -> 读取项目结构 -> 理解现有代码 -> 制定修改方案 -> 执行修改 -> 编译测试 -> 验证结果 -> 记录经验

## 详细步骤

### 第一步：需求分析

- 明确用户需求
- 识别技术约束
- 确定成功标准

### 第二步：读取项目结构

- 扫描项目目录
- 识别技术栈
- 了解文件组织

### 第三步：理解现有代码

- 读取关键文件
- 理解核心逻辑
- 识别依赖关系

### 第四步：制定修改方案

- 确定修改范围
- 设计实现方案
- 评估风险

### 第五步：执行修改

- 按方案修改代码
- 保持代码风格一致
- 不修改无关代码

### 第六步：编译测试

- 运行编译检查
- 运行单元测试
- 修复编译错误

### 第七步：验证结果

- 对照成功标准
- 检查是否有回归
- 确认功能正常

### 第八步：记录经验

- 记录修改内容
- 记录遇到的问题
- 记录解决方案

## 强制要求

1. 禁止修改代码后直接宣布完成
2. 必须回答：是否成功、如何验证、存在什么风险
3. 每完成一个模块自动检查
4. 每完成一个阶段自动生成开发日志
5. 修改文件前说明将修改哪些文件
6. 修改完成后列出修改文件清单

## 代码规范

- 保持现有代码风格
- 不引入不必要的抽象
- 不修改无关代码
- 删除自己修改造成的孤儿代码
