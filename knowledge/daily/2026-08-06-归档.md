## ⚠️ 发现的问题

### 问题 1：monitor.sh API 健康检查无效（严重度：中）

`~/.omlx/monitor.sh` 第 139 行使用占位符 `***` 作为 API key：
```bash
curl -sf --connect-timeout 10 http://127.0.0.1:8000/v1/models \
     -H "Authorization: Bearer ***" > /dev/null 2>&1
```

oMLX 的 `settings.json` 中 `api_key` 字段为空（`not found`），导致每次健康检查返回 401。虽然 LaunchAgent 的 KeepAlive 机制确保进程自动重启，但 monitor.sh 的日志会频繁记录"API 无响应，重启"的假阳性。

**建议**：从 `settings.json` 读取实际 API key，或移除 API key 检查改用其他方式验证服务。

### 问题 2：历史频繁误判重启（严重度：低）

从 `crash_monitor.log` 看，8月3日 21:54-22:17 期间，monitor.sh 每 2 分钟报告"进程不存在"并重启一次（共 8 次）。这很可能是早期 launchd 管理未就绪时的遗留问题，近期已恢复正常。
