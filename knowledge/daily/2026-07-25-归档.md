## 🐛 发现的问题和解决方案

### 问题 1：微博 API 发布失败
- **现象**：`opencli weibo publish` 报 `Could not find send button` (exit code 1)
- **根因**：`opencli` 包装层无法定位微博 UI 发送按钮，DOM 结构/自动化兼容问题
- **解决方案**：降级至 `opencli browser` 浏览器自动化，使用 `eval` 注入文案 + 点击按钮，已验证可行

### 问题 2：小红书配图路径错误
- **现象**：`opencli xiaohongshu publish` 报 `Image file not found: xiaohongshu_cover.jpg`
- **根因**：配图目录 `/Users/yaowei/ai-content-matrix/content/xiaohongshu/` 为空，指定文件不存在
- **解决方案**：用 Agnes 重新生成配图 `healing_cabin_01.png`，用正确路径重新发布，成功

### 问题 3：微博浏览器自动化 DOM 失配
- **现象**：`opencli browser weibo type` 报 `ref=0 not found in DOM`；会话曾跳转至 `about:blank`
- **根因**：微博页面 DOM 元素动态变化，`type` 命令基于固定 ref 索引，页面刷新后 ref 失效
- **解决方案**：改用 `eval` 直接操作 DOM；页面跳转时立即重新 `open` 微博并等待 3 秒加载

### 问题 4：oMLX 监控日志停滞
- **现象**：`crash_monitor.log` 最后一条记录停留在 2026-07-14 03:37:10，距今 11 天未更新
- **根因**：监控脚本的 cron 配置可能已失效或脚本本身停止运行
- **建议**：检查 `~/.omlx/monitor.sh` 的 cron 调度配置，确认脚本是否被正确执行

### 问题 5：web_extract 无法提取页面内容
- **现象**：`web_extract` 报错 `DuckDuckGo (ddgs) is a search-only backend and cannot extract URL content`
- **根因**：`web.extract_backend` 配置未正确生效，仍走 `ddgs` 后端
- **建议**：需配置 `web.extract_backend` 为 `firecrawl`、`tavily`（需有效凭证）、`exa` 或 `parallel`
