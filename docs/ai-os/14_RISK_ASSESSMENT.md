# 14 — Risk Assessment（风险评估）

> 依赖：01（红线）、12（路线图）、13（决策）
> 性质：架构/技术/产品风险识别与缓解；本 Sprint 仅评估，不实现。

---

## 1. 风险分级

- **Critical（严重）**：若发生，破坏 Local First 或单 Runtime 红线 → 必须零容忍。
- **High**：影响核心体验（崩溃丢目标、权限失效）。
- **Medium**：影响采用/维护（复杂度、耦合）。
- **Low**：体验瑕疵，可迭代。

---

## 5. 风险—红线映射总结

任何"Critical"风险都直接对应一条冻结红线（单 Runtime / Local First / 统一权限）。缓解措施**本身不得**违反其他红线——例如"为提升吞吐引入多进程"是禁项，必须用单 Runtime 内的受限并发解决（T1）。

---

## 6. 监控与门禁建议（供开发 Sprint）

- 每次提交跑"红线审计"：检测第二 Runtime / 直连 Executor / 契约不一致。
- 崩溃恢复专项测试：强制 kill 进程，验证目标不丢、步骤不重复（T3）。
- 同步冲突演练：模拟双向并发编辑，验证本地优先（T4）。

> 风险评估；实现由开发 Sprint 承接并加入门禁，本 Sprint 不写代码。
