# 小6 · 代码审查清单（CODE REVIEW CHECKLIST）

> 每条 PR 都必须逐条过此清单。标 🔴 的项未通过则**一票否决**，不得合入。

## 🔴 安全（一票否决）
- [ ] 无任何密钥/令牌硬编码（搜索 `sk-`、`AKID`、`password`、`api_key`、`secret`）。
- [ ] 新增外部调用密钥均来自 `.env` / 环境变量，且 `.env` 已被 `.gitignore` 忽略。
- [ ] 无 `eval` / `exec` / `os.system` 直接执行外部输入；如必须，已用白名单沙箱（参考 `tools._safe_eval`）。
- [ ] 新增文件/Shell/Web 工具：路径在白名单内、危险命令被拦截、操作写入审计日志。
- [ ] 外部 provider 异常被捕获并优雅降级，主链路不受影响。

## 🔴 数据与并发
- [ ] 所有 `sqlite3` 连接走 `db_conn()`（WAL + busy_timeout），不每请求裸连。
- [ ] 共享可变状态（缓存/订阅者/全局 dict）的读写有锁保护。
- [ ] 写操作（笔记/画像/提醒/任务）有明确的错误回显，不静默吞异常。

## 🟠 工程质量
- [ ] 没有把逻辑塞回 `server.py`；新代码落在正确模块。
- [ ] 函数职责单一，单文件不超过 ~400 行（超出请再拆）。
- [ ] 新增纯函数有对应 `tests/` 单测。
- [ ] `ruff check` 与 `ruff format --check` 全绿。

## 🟠 接口与兼容
- [ ] HTTP 接口返回结构未破坏前端既有契约（或已同步前端）。
- [ ] 数据库新增表/字段走迁移或 `IF NOT EXISTS` + `_migrate_*` 向后兼容。
- [ ] 新增第三方依赖已写入 `requirements.txt` 并标注是否可选。

## 🟢 体验与文档
- [ ] 前端交互/动画未被破坏（如有改动）。
- [ ] 关键设计决策已在 PR 描述或文档中说明。
- [ ] 命名/注释清晰，符合现有中文语境风格。
