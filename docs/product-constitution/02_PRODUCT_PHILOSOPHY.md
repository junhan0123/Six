# 02 · 产品哲学（Product Philosophy）

> 依赖：01（产品愿景）、Golden State（L0 红线）、`docs/ai-os/01_AI_OS_ARCHITECTURE.md` §2 冻结红线
> 红线：仅声明哲学/原则；不重定义技术真相，不引入新功能。

---

## 1. 为什么存在（Why We Exist）

小6存在，是因为主流 AI 产品把"你"锁进了云端黑箱：你的记忆、知识、上下文被割裂在互不连通的服务里，AI 对你的了解随会话终结而蒸发，且你无法真正拥有或审计它。

小6的反命题：**你的 AI 应该住在本地的你的机器上，记得你、懂你的知识、在你需要时安静地帮你，并且你能完全掌控它。**

---

## 2. 价值主张（What We Value）

1. **记得你**——记忆跨会话、跨项目、长期一致。
2. **懂你知识**——Obsidian 知识层，人类可读、可导航、可拥有。
3. **主动帮你**——薄主动层，在恰当时刻建议/提醒，不喧宾夺主。
4. **安全执行**——统一执行通道 + 权限门控，动作可追溯、可撤销。
5. **本地掌控**——Local First，离线可用、数据可携带、隐私即架构。
6. **一个 OS，不是一堆 App**——目标/工作流/智能体/插件统一于单一 Runtime。

---

## 3. 长期目标（Long-term Goal）

成为个人长期的、可信赖的 AI 副驾（Personal Long-term AI Copilot）——不是一次性问答工具，而是随你成长的、人格一致的数字伙伴，运行在你的本地环境中，越用越懂你，且永远在你掌控之内。

---

## 4. 设计原则（Design Principles）

> 以下原则与架构 10 原则（v2 核心架构规范）+ 2.0 增补（P11–P15）对齐，作为产品层的表达。

| 编号 | 原则 | 产品含义 |
|---|---|---|
| P-LF | **本地优先即信仰（Local First as Faith）** | 不是"功能开关"，而是架构底线。云端 LLM 仅作计算，永不持有你的状态。 |
| P-MEM | **记忆与知识是一等公民** | 记忆（关于你）与知识（关于世界）是产品的核心资产，而非聊天附件。 |
| P-THIN | **薄主动层（Thin Proactive）** | 小6可建议、可通知、可建目标，但**不能自己干**。主动行为可撤销、默认低打扰。 |
| P-SAFE | **可执行但安全（Safe Execution）** | 所有动作汇入单一执行通道，经权限闸门；高危动作须人确认；动作可撤销、可追溯。 |
| P-ONE | **单一运行时（Single Runtime）** | 无第二 Runtime / Memory / EventBus / Permission。简单即稳定。 |
| P-HON | **诚实（Honesty）** | 蓝图（missing）/ Mock（experimental）/ 未接线（hidden）不得伪装 production。 |
| P-OS | **OS 隐喻统一语言** | 用操作系统隐喻统一产品语言（文件系统=Vault、进程=Goal、权限=PolicyEngine…），降低认知负担。 |
| P-QUIET | **克制即尊重（Restraint = Respect）** | 默认安静。不打断、不刷存在感、不制造焦虑。存在感由用户召唤，而非索取。 |
| P-OWN | **用户拥有（User Owns）** | 你的数据、你的知识、你的配置、你的 AI 行为边界，都由你拥有与审计。 |

---

## 5. 不可违背原则（Inviolable Principles）

> 以下直接映射 Golden State（L0）红线，作为产品层不可逾越的底线。任何产品决策与之冲突即构成"架构漂移"，须回滚或走变更控制。

1. **无第二运行时 / 记忆 / 事件总线 / 权限系统**——产品不得暗示或设计两套并行系统。
2. **Vision 仅观察，绝不控制**——感知用于理解，不用于动作。
3. **所有执行必经权限闸门**——无绕过 `PermissionGuard` 的动作。
4. **状态唯一写入口**——产品体验不得暗示"第二份状态"。
5. **Local First 不可妥协**——不把"云能力"包装成本地能力；离线须可用。
6. **不牺牲 OS / Local First 换功能多**——任何新模块若不能强化 OS/Local First，先质疑再纳入。
7. **不模仿"无限自动执行 Agent"叙事**——我们克制、可撤销、可审计。

## 6. 哲学的落地纪律（与既有治理衔接）

- 任何涉及"能力增删改"的产品想法 → 先过 `docs/capability-platform/v1.1/03_AGENT_CAPABILITY_CHECK_PROTOCOL.md`（G1–G8 闸门）。
- 任何"主动/执行"产品想法 → 须符合 P-THIN / P-SAFE 与架构 P11–P13。
- 任何"新模块"产品想法 → 不得破坏 P-ONE / L0 红线；超出须走 `docs/decisions/` Decision 流程。
