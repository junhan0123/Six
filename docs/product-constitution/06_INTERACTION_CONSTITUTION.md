# 06 · 交互宪法（Interaction Constitution）

> 依赖：能力真相（`03_ENTRY_MAP.md` 入口地图）、03（体验原则）、05（暴露级别）
> 红线：仅界定各交互面职责与边界；不引入新交互、不改动代码、不重定义能力真相。

---

## 1. 目的

小6有多个交互面（Galaxy / Companion / Overlay / Toast / Notification / Dock / Panel / Command / Voice / Chat / Keyboard / Mouse）。本文件明确**每个面的唯一职责**，禁止职责重叠造成的认知混乱与重复系统（引用 `05_DUPLICATE_REPORT.md`：Toast 5+、Overlay 12+）。

> 原则：**一个意图，一个主交互面；每个面只做一件事，且做到底。**

---

## 2. 交互面职责矩阵（唯一职责）

| 交互面 | 唯一职责 | 承载能力（暴露级别） | 禁止 |
|---|---|---|---|
| **Galaxy** | 状态/关系的**背景可视化**（太阳系隐喻） | 只读投影（T3 展示） | 不得持有业务状态、不得改银河本体、不得作为操作入口 |
| **Companion** | 常驻**伴侣浮窗**：快速对话/菜单/勿扰 | 对话 T0、菜单 T1、勿扰开关 | 不得承载复杂面板；不得自行执行动作 |
| **Overlay** | **模态/上下文层**（确认、详情、沉浸） | 权限确认（P-SAFE）、场景卡 | 不得与 Toast 抢屏；须收口到统一 OverlayManager |
| **Toast** | **瞬时轻提示**（2–3s 自动消失） | 提醒 T0/T1、后台结果 | 不得承载交互按钮（除"忽略"）；须统一通道去重 |
| **Notification** | **持久未读/角标**（可累积） | 提醒/累积项（睡眠态） | 不得弹窗抢焦点；与 Toast 分清"瞬时 vs 持久" |
| **Dock** | **底部指令坞**：输入/语音/截图/快捷命令入口 | 输入 T0、语音 T1、拖文件 | 不得展开为完整面板 |
| **Panel** | **业务信息面板**（天气/监控/记忆/知识…） | T0/T1 信息呈现 | 不得彼此重叠；统一面板管理 |
| **Command Palette** | **统一指令中心**（Ctrl/Cmd+K） | T0/T1 全部可召唤能力 | 唯一指令中心；不得另建第二命令系统 |
| **Voice** | **语音输入/输出通道** | 语音输入 T1、TTS 输出 | 不得绕过文字通道的权限；ASR 当前未接真实（Mock） |
| **Chat** | **自然语言主入口** | 对话 T0、意图→Goal | 不得成为唯一入口（仅为入口之一） |
| **Keyboard** | **快捷键层**（全局） | `,` 设置 / `/` 聚焦 / Esc 关闭 / Ctrl+K 指令 | 不得有 18+ 去中心化 Esc 监听（焦点管理须集中，见 10） |
| **Mouse** | **点击/拖拽** | 面板按钮、Dock、拖文件 | 不得隐式触发高危（高危须显式确认） |

---

## 3. 禁止重叠（Non-Overlap Rules）

1. **Toast ≠ Notification**：Toast 瞬时（自动消失），Notification 持久（角标/未读）。同一消息不双发。
2. **Overlay ≠ Panel**：Overlay 是模态/上下文层（确认、沉浸），Panel 是常驻信息。确认框一律 Overlay，不用 Panel 模拟。
3. **Companion ≠ Panel**：Companion 只做浮窗级（对话/菜单/勿扰），复杂信息交给 Panel。
4. **Command Palette 唯一**：不得有第二命令系统（已有 `command-palette.js` 为唯一，无重复）。
5. **Galaxy 不操作**：Galaxy 仅可视化，所有操作经由 Chat/Command/Dock/Panel。
6. **Dock 不展开**：Dock 是入口坞，不是面板容器。

---

## 4. 统一通道要求（去重）

- **提示统一**：所有轻提示经统一 Toast 通道（消除 Toast 5+ 重复，`05_DUPLICATE_REPORT.md`）。
- **模态统一**：所有模态经统一 OverlayManager（消除 Overlay 12+ 重复，`05` D 系列）。
- **指令统一**：所有命令经 Command Palette（已唯一）。
- **焦点统一**：Esc/焦点管理集中（消除 18+ 去中心化 Esc 监听，`03_ENTRY_MAP.md` §十一）。

---

## 5. 交互与体验原则的关系

- 所有主动/提醒/介入内容经 03 六态框架发出；本文件决定"由哪个面承载"。
- 介入（高风险确认）→ Overlay（模态，强制聚焦）。
- 提醒（低优先）→ Toast（瞬时）或 Notification（持久角标）。
- 主动（建议）→ Companion/Notification（可忽略，不弹窗）。

---

## 6. 现实约束（诚实）

- **Electron 原生交互不存在**：托盘、全局快捷键、原生菜单、主进程 IPC 均无（`03_ENTRY_MAP.md` §十）。当前所有交互为浏览器事件；涉及"原生常驻/全局快捷"的设计须标注"需 Electron 立项"。
- **语音真实能力未接**：ASR/Voice 当前为 Mock，交互设计须标注"规划中"。
- **Ctrl/Cmd+U "打开宇宙视图"为死快捷键**（提示但无处理），不得作为可用能力宣传。

---

## 7. 本文向下约束

- 07 信息架构须把上述交互面组织到对应层级。
- 08 用户心智模型中"各面是什么"须与本职责一致。
- 09 AI 行为中"用什么面表达"须符合本宪法（介入→Overlay、提醒→Toast/Notification）。
- 10 路线图中 UI 收口（Toast/Overlay/焦点）须落地本宪法要求。
