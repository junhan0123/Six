# 03 · 体验原则（Experience Principles）

> 依赖：02（产品哲学 · P-THIN/P-QUIET/P-SAFE）、架构 P11–P13、Golden State（L0）
> 红线：仅定义体验何时主动/等待/安静/提醒/介入/退出；不引入新功能、不改动代码。

---

## 1. 总纲：克制即尊重

小6的体验第一性原则是**克制**。默认安静，存在感由用户召唤而非索取。主动行为是可撤销、低打扰、可解释的。

本文件规定小6在六个体验态之间的取舍：**主动 / 等待 / 安静 / 提醒 / 介入 / 退出**。

---

## 2. 六态定义与边界

### 2.1 主动（Proactive）
- **定义**：无需用户触发，后台 tick 驱动的建议/通知/建目标（对应 `PRO-01..05`）。
- **允许**：汇总、提醒、轻建议、建草稿目标待确认。
- **禁止**：自行执行动作、自行修改状态、自行发消息、自行控制电脑（P13 薄主动层）。
- **强度**：默认低打扰；可被"勿扰"模式完全压制。

### 2.2 等待（Wait）
- **定义**：驻留待命，监听用户输入/事件，但不产出任何主动内容。
- **适用**：用户明确在工作、会议、游戏等"请勿打扰"上下文（见 04）。
- **原则**：等待不是"消失"，而是"安静在场"。

### 2.3 安静（Quiet / Ambient）
- **定义**：界面元素存在但不发声、不闪动、不抢焦点。
- **适用**：Companion 浮窗常驻、Galaxy 背景、Dock 常驻但静态。
- **原则**：视觉存在 ≠ 听觉/认知打扰。安静是默认视觉态。

### 2.4 提醒（Remind）
- **定义**：在恰当时间推送一条低优先级通知（Toast / 伴侣角标）。
- **允许**：待办到期、目标里程碑、知识缺口、日程临近。
- **禁止**：连续刷屏、重复提醒同一件事、在非工作时间强提醒。
- **去重**：同一提醒源 24h 内不重复（引用能力真相中 Toast 5+ 重复问题，提醒须走统一通道，见 06）。

### 2.5 介入（Intervene）
- **定义**：在用户可能犯错或面临风险时主动打断。
- **允许**：执行高危动作前的权限确认（P-SAFE）、检测到冲突目标、检测到数据风险。
- **强度**：仅"高风险/不可逆"才介入；低风险一律等待或提醒。
- **原则**：介入必须有明确理由且可解释；不得为"显得智能"而介入。

### 2.6 退出（Exit / Step Back）
- **定义**：主动让出控制权、收起自己、回到等待。
- **触发**：用户明确"不用了/停止"、任务完成且无需后续、用户进入深度专注。
- **原则**：退出要干净——不留悬空监听、不悄悄继续动作、不残留状态。

---

## 3. 触发矩阵（何时用哪一态）

| 情境 | 首选态 | 说明 |
|---|---|---|
| 晨间简报（用户已醒/已开） | 主动→提醒 | 一条汇总，可忽略 |
| 目标临近到期 | 提醒 | 单条，不刷屏 |
| 用户正在输入/会议中 | 等待 | 完全静默 |
| 检测到将执行删除/杀进程 | 介入 | 权限确认，高风险 |
| 后台知识监听有新关联 | 安静（角标） | 不弹窗 |
| 用户说"停下" | 退出 | 立即收起 |
| 长时无交互 | 安静 | 浮窗常驻静态 |

---

## 4. 打扰预算（Interruption Budget）

- 单用户单日主动推送 ≤ **N 条**（N 由实现阶段定，产品层规定"极少"）。
- 同一来源提醒 24h 内 ≤ 1 次。
- "勿扰"模式（伴侣菜单）一旦开启，除"介入（高风险）"外全部压制。
- 任何主动内容必须可一键忽略且不复发。

---

## 5. 可解释性（Explainability）

- 每一条主动/提醒/介入内容，用户应能追问"为什么"并得到可理解理由。
- 主动建的目标须标注"由小6建议"，用户确认后才激活（薄主动层）。

---

## 6. 与底层真相的关系

- 主动行为受 `docs/ai-os/01_AI_OS_ARCHITECTURE.md` P13（薄主动层）约束：只能 SUGGEST/NOTIFY/CREATE_GOAL，不能自执行。
- 介入（高风险确认）复用 Execution Platform 权限闸门（`docs/ai-os/execution-platform/`），不另建确认机制。
- 提醒通道须收敛到统一 Toast/Overlay（引用 `05_DUPLICATE_REPORT.md` 中 Toast 5+ 重复问题，未来 UI 收口见 10 路线图）。
