## 4. 团队技术提升方案（核心交付）

目标：把「老板 + 强单兵」的能力，固化成**团队可复制的工程标准**。四条主线：

### 4.1 工程纪律（最高杠杆）
1. **全部代码进 git**：初始化仓库、建 `develop`/`main` 长期分支 + 功能分支 `feat/*`。
2. **强制 Code Review**：任何合并进 `develop` 必须 ≥1 人 review；PR 模板含「变更说明 / 测试 / 风险」。
3. **提交规范**：采用 Conventional Commits（`feat:`/`fix:`/`refactor:`）。
4. **建 ADR（架构决策记录）**：把「为何用纯标准库 / 为何云端大脑」等决策写下来，避免反复争论。

### 4.2 质量门禁（自动化）
1. **`pre-commit` + CI 流水线**：`ruff`(lint) → `black`(format) → `mypy`(类型) → `pytest`(单测) 四级门禁，不过不让合。
2. **覆盖率门禁**：核心纯函数单测覆盖率 ≥80%；e2e 在 CI 里用 mock Agnes 跑（避免依赖真实 key/网络）。
3. **安全扫描**：`detect-secrets` 防密钥误提交（补 P1-2 的窟窿）。

### 4.3 架构解耦（可维护性）
把 `server.py` 按职责拆分为：

```
xiao6-ui/
├── server.py            # 仅做装配：路由 + 启动
├── core/
│   ├── chat.py          # run_fc_loop / detect_intent / system prompt 组装
│   ├── memory.py        # SQLite 连接管理(WAL) + 记忆压缩 + 画像
│   └── tools.py         # TOOLS 声明 + 工具执行器 + 并行调度
├── services/
│   ├── weather.py       # 天气（wttr/open-meteo）
│   ├── hotspots.py      # 热榜多源抓取
│   ├── geo.py           # IP 定位
│   └── sysmon.py        # 系统监控
├── infra/
│   ├── http.py          # 唯一 _http_get_json（去重 P1-1）
│   └── config.py        # 环境变量 + 密钥加载（含 HOTDATA_KEY 移出源码）
└── tests/               # pytest 单测 + e2e（mock Agnes）
```
拆分原则：**先抽 `infra` 和 `services`（低风险、无业务逻辑耦合），再抽 `core`，最后动 `server.py` 装配**。每步一个 PR，可独立 review。

### 4.4 知识沉淀与复审文化
1. 每周一次 **Code Review 半小时**：挑一段代码集体挑刺，培养「读别人代码」的习惯。
2. 建立 **团队代码规范文档**（基于本评审 3.2 的问题清单 + 4.3 的目录约定）。
3. 新人 onboarding 用小6项目做「重构练习」：拆一个 services 模块练手。
