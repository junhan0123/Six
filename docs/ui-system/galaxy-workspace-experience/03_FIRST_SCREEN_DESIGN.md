## 0. 设计目标

启动第一屏必须**在一秒内同时呈现「世界」与「操作台」**，让用户立即建立「一个 AI 空间」的心智——而非「一个聊天框 + 一个背景图」。

## 2. 各区域第一屏设计决策

### 2.1 背景 / Galaxy 可见程度
- **默认暗化常驻**（~30% 亮度遮罩），太阳与主要轨道/星球清晰可辨，作为「世界在场」信号。
- **不抢占操作台**：中央放置轻量前景玻璃，而非全屏 hero（Consolidation 已将 hero 降为水印徽章，沿用）。
- 状态节点保持克制可见（占位色），流星偶现作主动推送轻提示。
- **禁止**：全屏 onboarding 遮挡（已修）；禁止银河被 `.app` 彻底遮盖（现状 S1，UI-3B 修正）。

### 2.2 Workspace 位置
- **没有「进入 Workspace」动作**：启动即处于操作态，前景玻璃操作台即工作台。
- 主内容区（中央/右栏）承载当前焦点（对话/任务/上下文），默认低密度。
- 右下/底部常驻 Command Dock 与 Execution Timeline。

### 2.3 Command Dock 位置
- **永驻于底部**（替代现状「仅 Home 有 Dock」的 S7）。
- 横向五合一：文本 / 语音 / 文件 / 截图 / 快捷（`command-dock.js:26-36`）。
- 探索态下可半透明退后但仍可达（不消失）。

### 2.4 AI Presence 位置
- **HUD 状态点（--z-hud 20）** 常显 `IDLE/THINKING/...` 文本+色点（`index.html:85, avatar-state.js`）。
- **Companion 化身（--z-companion 9999）** 常驻角落，非阻塞（`avatar-state.js` 派生）。
- 两处同源（同一 AvatarState 派生），任何态均可见。

### 2.5 信息密度
- **默认低密度**：HUD + Dock + 1 状态点 + 右栏抽屉（收起）。
- Matrix/Insight 默认收起为右栏抽屉入口（`osContextToggle`，`index.html:89`），用户主动展开。
- 银河不加数据标签噪声；节点信息仅在聚焦时经 gx-card 出现（`galaxy-experience.js:77-123`）。

## 6. 首启体验（First Launch Experience）

首启用户（第一次打开小6）的目标是**在一秒内建立「这是一个 AI 操作系统、有一个活着的 AI 世界」的感知**，而不是被信息淹没。因此首启采用**渐进式披露（progressive disclosure）**：三段时间轴（1s/5s/30s，见 01 §1）对应三档逐步展开的世界感，**严禁把全部引导信息一次性堆叠到第一屏**。

### 6.1 第一秒 · 世界在场（Arrival）
- 启动即呈现「暗化银河世界层 + 前景玻璃操作台」，与回流用户共用同一套第一屏布局（§1）。
- **不做**全屏 onboarding 教学弹窗（Consolidation 已修）；不堆叠「欢迎语 + 功能列表 + 引导箭头」三件套。
- 仅以 HUD 一处极克制的品牌 + AI Presence `IDLE` 状态点，暗示「这台 OS 是活的」。
- 判定：用户 1 秒后能用一句话描述「这是一台有世界的 AI，不是聊天框」。

### 6.2 第五秒 · 世界可理解（Orientation）
- 通过**环境暗示**而非文字教学让用户理解结构：银河中太阳（核心）明亮、轨道（Goal）与星球（能力域）可见，天然传达「状态机宇宙」。
- Command Dock 处于待命，hint 仅一行：「输入指令，或 `Ctrl/Cmd+K` 召唤命令面板」——一句即够，不展开功能清单。
- 右栏上下文抽屉默认收起（§2.5），仅留入口，不主动铺开。
- 判定：用户 5 秒后能说清「银河=世界，Dock=主入口，右栏=上下文，Panel=功能」。

### 6.3 第三十秒 · 世界可操作（Act）
- 用户在 Dock 输入第一条指令 → 立即在工作台得到响应，银河不退场（仅暗化）。
- 或 `Ctrl/Cmd+K` → Command Palette 一次搜索发现功能。
- 或点一颗星球 → 经 `galaxy-experience` 聚焦进入能力面板（DECISION_004）。
- 判定：30 秒内完成「下达指令 / 打开一个功能面板 / 聚焦一个能力域」之一。
- **首启 vs 常态一致**：首启的三十秒体验，就是回流用户的日常操作流——不存在「首启专属流程」与「日常流程」的分裂。

> 首启体验核心纪律：**用世界本身说话，不用引导层说话**。一切引导信息密度受 01 §7 Attention Budget Principle 约束。

## 7. 回流用户体验（Returning User Experience）

回流用户（已建立心智、回来继续工作）的目标与首启相反：**不要再用世界感教育我，直接把我放回我离开时的状态**。回流第一屏在保持同一套布局（§1）的前提下，信息重心从「世界感知」转向「当前上下文」。

回流用户第一屏的四要素（按信息层级 01 §4 收口）：

| 要素 | 内容 | 承载位置 | 注意力态 |
|---|---|---|---|
| **当前状态** | AI Presence 当前态（IDLE/THINKING/…）+ 最近一次同步/执行结果摘要 | HUD 状态点 + 右栏上下文抽屉顶部 | Peripheral（默认即可见，不抢焦点） |
| **当前任务** | 进行中/挂起的任务与执行进度，可一键续接 | Execution Timeline（空闲折叠，有则展开）底部 Dock 上方 | Secondary Focus（≤2 之一） |
| **AI 上下文** | 最近的 Memory / Goals / 对话摘要，帮助快速找回思路 | 右栏上下文抽屉（默认收起，回流可一键展开到上次位置） | Peripheral / Secondary |
| **快速操作** | 最常用意图的快捷入口（续接上次任务、召唤命令面板、进入某能力域） | Command Dock 快捷槽 + 右栏快捷 | Secondary Focus |

### 7.1 回流与首启的差异纪律
- **同一布局，不同信息权重**：回流用户不做「世界感重新教育」，银河仍暗化常驻但不再是注意力焦点；重心上移到底部 Dock 与右栏上下文。
- **恢复而非重置**：若上次离开时某面板处于 Active，回流时可恢复到 Attention（唤起）态而非强行 Dormant（见 04 §13 Panel Lifecycle），但**不**自动跳到 Active 抢占主焦点（守 Attention Budget）。
- **不弹引导**：回流用户永不看到首启 onboarding 痕迹；引导层只在首启且用户未显式请求时出现。

> 回流体验核心纪律：**用户的时间线在小6里是连续的**，第一屏是「我离开时的延续」，不是「重新认识一个产品」。
