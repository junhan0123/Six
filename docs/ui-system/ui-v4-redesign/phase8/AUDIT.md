> 审计视角：Senior Product Designer + Frontend Architect
> 审计时间：2026-08-10

## 0. 结论先行

Phase 7 交付的是一个**架构正确、但人格缺席**的界面。

| 维度 | 判定 |
|---|---|
| 架构（单空间 / 单核心 / 单入口） | ✅ 成立 |
| 数据真实性 | ⚠️ 部分失真（存在 P0 解析缺陷） |
| 视觉是否达到 Personal AI OS | ❌ 未达到 |
| 用户第一眼能否认出「这是小6本人」 | ❌ 不能 |

**一句话诊断：现在这一屏像一个"状态查看器"，不像"一个人在等你"。**

## 1. 五大部件逐项审计

### 1.1 AI Core

**现状**
- DOM 为 `.ai-core__halo`（模糊圆）+ `.ai-core__ring`（描边圆）+ 文本块。
- 光晕靠 `top:-120px` 绝对定位，身份文本靠 `margin-top:188px` 硬撑开。
- 名字 30px、状态标签 12px mono 大写字距，二者 `baseline` 并排。

**问题**

| 编号 | 级别 | 问题 |
|---|---|---|
| C-1 | P1 | **无"核"**。只有一团光晕和一个空环，中心是空的——视觉上没有"他本人"，只有"他的场"。 |
| C-2 | P1 | **布局靠魔法数字**（`-120px` / `188px`）。改任何字号都会错位，不可维护。 |
| C-3 | P1 | 名字与状态**并排同行**，读起来是「小6 · IDLE」这样的标签，像进程名而不是称呼。 |
| C-4 | P1 | 八态里**只有 executing / thinking 有动画**，其余五态视觉完全一致 → 状态不可感知。 |
| C-5 | P2 | `aria-live="polite"` 挂在整个 section 上，屏读器会重复朗读身份文案。 |

**是否符合 Personal AI OS：否。** 它是一个 Loading 指示器的高级版本，不是一个"存在"。

---

### 1.2 Presence State（八态表达）

**现状**
- `ai-core.js` 的 `STATE_MAP` 把后端态映射到 AvatarState，取 `META[x].label` 直接显示。
- 显示结果为：`待命` / `思考中` / `执行中` / `异常` / `离线`。

**问题**

| 编号 | 级别 | 问题 |
|---|---|---|
| S-1 | P1 | **词典标签不是表达**。「待命」「异常」是运维术语；小6应该说人话。 |
| S-2 | P1 | 状态切换是**文字硬跳**，没有过渡，观感廉价。 |
| S-3 | P1 | `current_goal` 直接渲染为 **`目标 #7`** —— 技术 ID 泄漏到 Presence 层。 |
| S-4 | P2 | `STATE_MAP` 缺 `failed`/`completed`/`offline` 等别名，后端换词即降级为 IDLE。 |

**取样佐证**：`GET /api/agent/state` 实返 `{"enabled":true,"state":"IDLE","current_goal":null,...}`；
`agent_runtime.py:23` 确认编排态字面值为 **大写** `IDLE/PLANNING/EXECUTING/REFLECTING`。

### 1.3 Context Layer

**现状**
- 三行，每行前缀一个 mono 大写标签：`DOING` / `KNOWN` / `WORLD`。
- 文案模板：`我正在：推进「X」`、`我记得：…`、`我理解：…等主题领域`。

**问题**

| 编号 | 级别 | 问题 |
|---|---|---|
| **X-1** | **P0** | **记忆永远是空的。** `data-adapter.js` 按 `{memories:[]}` 解析，而 `/api/memories` 实际返回**数组**。→ `snap.memories` 恒为 `[]` → 「我记得」永远走兜底文案，记忆抽屉永远显示"还没有记忆"。**这是一处静默的数据谎言。** |
| **X-2** | **P0** | 「我理解」取 `d.category \|\| d.type`，真实值是 **`concept`**，于是渲染成 **「我理解：concept等主题领域」**——英文 slug 直接漏进中文句子。 |
| **X-3** | **P0** | 目标取 `goals[0]`。真实数据里 7 条目标有 **6 条同名**（"总结当前项目状态"），且首项 `progress:0`，而真正推进到 **83%** 的是 id=5。→ 首页展示的是最没有信息量的那一条。 |
| X-4 | P1 | `DOING / KNOWN / WORLD` 大写 mono 前缀 = **HUD 标签**，正是"数据展示"而非"语义表达"的病征。 |
| X-5 | P1 | 三行权重完全相同，没有主次，读者不知道先看哪句。 |
| X-6 | P2 | 与 AI Core 的 `setDoing()` **重复表达同一个目标**（核心区说一遍、上下文再说一遍）。 |

**是否符合"AI 语义表达"：否。** 它是三个带标签的数据槽位。

### 1.4 Intent Line

**现状**
- 胶囊输入框 + 常驻实心圆形发送按钮（背景 = 当前状态色）。

**问题**

| 编号 | 级别 | 问题 |
|---|---|---|
| I-1 | P1 | **中文输入法回车会误提交**：组词状态下按 Enter 确认候选词，会被 form submit 吞掉。中文用户必踩。 |
| I-2 | P1 | 发送按钮**恒为实心状态色**。ERROR 态时变成一枚**红色实心主按钮**——红色在界面语义里是"危险"，与"发送"冲突。 |
| I-3 | P2 | 占位文案是旁白口吻（"正在执行任务…"），不是小6在说话。 |
| I-4 | P2 | 空输入也可点击，无 ready 反馈。 |

---

### 1.5 Overlay

**现状**
- 右侧抽屉，`.ov-item` 行 + `.ov-section-label` 分组。

**问题**

| 编号 | 级别 | 问题 |
|---|---|---|
| O-1 | P1 | 标题只有裸词「记忆/知识/项目」，**没有人称**——和系统设置面板无异。 |
| O-2 | P1 | 记忆行直接展示后端原文 **`Hotspot event: 原来古诗词里的河南真的存在`**，机器前缀暴露，像日志查看器。 |
| O-3 | P1 | 空态文案是「还没有记忆。」「知识库为空。」——**系统口吻**，冷。 |
| O-4 | P2 | 无焦点管理：打开抽屉焦点仍在背景，关闭后焦点丢失。 |
| O-5 | P2 | World 关系图为单圈布局，节点标签**必然互相压叠**（真实数据 30+ 节点）。 |
| O-6 | P2 | 点击同一个 nav 点不能收起，只能靠 Esc / 点遮罩。 |

## 2. 视觉语言总体审计

| 维度 | 现状 | 目标（Apple + Claude + Linear） | 差距 |
|---|---|---|---|
| 深色空间 | `#0a0c10` + 两团渐变 | 近黑 + 纵深 + 细颗粒 | 平，缺质感 |
| 留白 | 固定 px 间距 | 随视口呼吸的节奏 | 偏挤 |
| 单色强调 | 状态色已单一 ✅ | 保持 | 达标 |
| 微动效 | 仅 2 态有动画 | 八态各有节律 + 进场编排 | 严重不足 |
| 排版 | 30px/14px/13px 三档，无字距体系 | display / kicker / body 分层，中文字距 | 未成体系 |
| 导航 | 汉字实心圆「记知项界设」 | 静默点，悬停才显名 | 控制台味 |
