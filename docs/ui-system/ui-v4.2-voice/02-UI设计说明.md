# 小6 UI · v4.2 Voice Presence Layer — UI 设计说明

> 身份：Senior AI Interaction Designer + Frontend Architect
> 目标：在 v4.1 AI OS 基础上，把「麦克风按钮」重构为「小6的听觉入口（Voice Orb）」，强化存在感。
> 红线：不新增事件 / 不修改后端 Runtime / 不新增页面 / 不建第二个聊天框。

---

## 一、产品判据（验收锚点）

打开小6，用户感觉：

> **「小6正在听我说话。」**

而不是：

> 「我点击了一个麦克风按钮。」

设计围绕这一句展开：Voice Orb 不是控件，是小6感知你声音的那一层。

---

## 二、Voice Orb 设计语言

### 2.1 归属
Voice Orb **属于 AI Core**，与中央光核同源同语。它不是独立按钮，而是光核外圈的一层「听觉场」——平时隐没，当你要对小6说话时，它亮起、呼吸、泛起声纹。

### 2.2 视觉
- **同一设计语言**：声纹与光核共用 `--core-color`（整屏唯一强调色，随小6状态变化），绝不用第二套配色。
- **柔和光晕**：声纹为多层同心圆环，淡入淡出，不刺眼。
- **呼吸**：监听态下麦克风标记随光核一起缓慢呼吸。
- **声音响应**：监听时声纹向外扩散（小6在接住你的声音）；回应时声纹更密更快（小6在回应）。
- **非按钮化**：无描边方块、无「麦克风」图标按钮底色；麦克风标记只在光核下方做极淡提示，悬停才微亮。

### 2.3 DOM 结构（新增于 `#aiCore` 内，包裹既有 `.orb`）
```
<div class="presence__corewrap">
  <button class="voice" id="voiceOrb" aria-label="让小6听你说" aria-pressed="false">
    <span class="voice__halo"></span>            <!-- 声纹环 1 -->
    <span class="voice__halo voice__halo--2"></span> <!-- 声纹环 2（错相位） -->
    <span class="voice__mic"><svg>…麦克风…</svg></span> <!-- 极淡提示，悬停微亮 -->
  </button>
  <div class="orb" aria-hidden="true"> …（既有 三层 + satellite） </div>
</div>
```
`.voice` 覆盖光核区域、`pointer-events:auto` 可点；声纹 `pointer-events:none` 仅作视觉。

## 三、五态表达（IDLE / LISTENING / PROCESSING / SPEAKING / ERROR）

状态以 `data-voice="<state>"` 写在 `#aiCore` 上，由 CSS 表达；不新增任何前端事件。

| 状态 | 触发 | 视觉 | 副文案（`#aiCoreDoing`，复用既有行） |
|---|---|---|---|
| `IDLE` | 默认 / 停止 | 声纹隐没，仅极淡麦克风提示 | （空） |
| `LISTENING` | 点击/快捷键/唤醒词命中 | 声纹向外扩散、呼吸；麦克风标记亮起为 `--core-color` | 「我在听，说吧」 |
| `PROCESSING` | 识别到一句话、正投给小6 | 声纹收束、加快脉动 | 「收到，我来处理」 |
| `SPEAKING` | 语音指令投出后，小6经 `agent_state` 进入执行/完成 | 声纹更密更快（小6在回应） | 「我来处理」 |
| `ERROR` | 麦克风未授权 / 识别不可用 | 声纹转为 `--voice-error`（#ff6b6b）一次轻脉冲 | 「麦克风没开，去设置里允许一下」 |

> ERROR 色 `--voice-error` 取自 avatar-state `ERROR` 同值（`#ff6b6b`），保持单一来源。

## 四、与 AI Core 八态的生命联动

Voice Orb 的五态与 AI Core 八态**正交共存**（分别写在 `data-voice` 与 `data-state` 两个属性上，互不覆盖），共同构成「小6的生命反馈」：

```
你开口  →  LISTENING（声纹扩散，小6在接）
你停   →  PROCESSING（声纹收束，小6在想）
投出意图 →  agent_state 推进 → SPEAKING（声纹加速，小6在做/在回应）
完成   →  IDLE / 继续 LISTENING（若你还在说）
```

- **链路复用**：SPEAKING 反馈完全由既有 `agent_state` SSE 驱动（`V4Data.onAgentState`），仅当该次意图确由语音投出（`voiceDispatchAt` 在窗口内）才点亮——键入的意图**不会**误触发 SPEAKING。
- **唤醒词**：订阅既有 `wakeword_detected` SSE，命中即进入 LISTENING（无接触唤醒）。

---

## 五、Intent Line 联动

- 识别**过程**：实时文本经 `V4Intent.setText(transcript)` 流入既有 Intent Line 输入框（实时字幕，非第二个聊天框）。
- 识别**完成**：`V4Intent.submit(finalText)` → 既有 `ZZIntentGateway.dispatch` → `POST /api/agent/intent`（与键入同一后端链路）。
- 一句话识别即一次投出；连续监听模式下逐句投出。

---

## 六、数据连接（消费既有，零新增）

```
浏览器采集音频 ──POST /api/asr?ext=.webm──▶ 后端 asr.py（FunASR/Vosk/Whisper）──▶ 文本
        │                                                                              │
        └──（降级）SpeechRecognition(zh-CN) 原生 STT ─────────────────────────────────┘
文本 ──V4Intent.submit──▶ ZZIntentGateway.dispatch ──▶ /api/agent/intent ──▶ Intent Gateway ──▶ Agent Runtime
状态反馈：wakeword_detected SSE（唤醒）· agent_state SSE（SPEAKING 联动）· 均既有，无新增事件
```

---

## 七、交互入口（去按钮化）

- **主交互**：点击中央光核（Voice Orb 覆盖区）即切换「听 / 不听」。
- **快捷键**：`Ctrl+Shift+U` 切换（不与现有 ⌘1–5 / Esc 冲突）。
- **无接触**：`wakeword_detected` SSE 命中自动进入 LISTENING。
- **降级提示**：不支持语音的浏览器，点击后给出温和文案「这个浏览器还不支持语音，打段字也行」，不报错崩溃。

---

## 八、红线自检（设计阶段）

- ✅ 不新增事件：仅订阅既有 `wakeword_detected` / `agent_state` SSE。
- ✅ 不修改后端/Runtime/EventBus/AppState/Goal/Memory：改动限于 `xiao6-ui/v4/`。
- ✅ 不新增页面、不建 Dashboard、不恢复 Galaxy：Voice Orb 是 AI Core 的一层。
- ✅ 优先复用：实时识别走既有 `/api/asr`；识别文字走既有 Intent Gateway。
- ✅ 不重造语音 Runtime：浏览器仅采集音频，识别交后端既有 ASR；降级才用平台 STT。
