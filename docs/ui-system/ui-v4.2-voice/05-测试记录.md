## 三、后端能力探测（决定实际识别路径）

```
GET /api/asr/status → { provider:null, enabled:false, local:false,
  available:{ whisper:false, vosk:false, local:false, aliyun:false, xfyun:false, volcengine:false } }
```

结论：本沙箱后端 ASR 未启用（FunASR/Vosk/Whisper 未安装、无云端密钥）。
→ 按设计，**voice-presence.js 自动降级为浏览器原生 `SpeechRecognition(zh-CN)`**，Voice Orb 仍可工作。
→ 若部署环境启用了后端 ASR，则主路径 `POST /api/asr` 生效（真实复用 FunASR/Vosk/Whisper），无需改代码。

## 五、交互验证清单（浏览器手动确认项）

以下需在 Chrome/Edge（支持 `webkitSpeechRecognition`）打开 `http://127.0.0.1:8121/v4/` 人工确认：

1. **默认态**：光核下方仅有极淡麦克风提示，无声纹；整屏观感与 v4.1 一致（无新增噪音）。
2. **点击光核 / `Ctrl+Shift+U`**：进入 LISTENING —— 声纹向外扩散、麦克风标记亮为当前强调色、`#aiCoreDoing` 显示「我在听，说吧」。
3. **说话**：识别文字实时出现在 Intent Line 输入框（中文 `SpeechRecognition` 中转写）。
4. **停顿**：一句话识别完成 → PROCESSING（声纹收束）→ 文字提交 → 小6经 `agent_state` 给出 SPEAKING 脉冲（声纹加速）→ 归位（若仍活动则继续 LISTENING）。
5. **再次点击 / 快捷键**：停止监听，归位 IDLE。
6. **无接触唤醒**（若后端启用 `XIAO6_KWS_ENABLED`）：命中唤醒词 → 自动 LISTENING。
7. **拒绝麦克风授权**：进入 ERROR 态（红色声纹一次轻脉冲）+ 文案「麦克风没开，去设置里允许一下」→ 归位。
8. **红线确认**：浏览器 Network 面板中语音文字走 `POST /api/agent/intent`（与键入同一链路）；无新增 SSE 事件类型。

## 六、已知限制（透明记录）

- 无头环境无法驱动真实麦克风，故「识别准确率 / 端到端延迟」未做实测；逻辑与降级路径已通过代码审查与线上服务核对确认。
- 后端 ASR 在本沙箱关闭，端到端语音识别依赖浏览器 STT 降级；生产环境启用后端 ASR 后自动切换主路径。
- `SpeechRecognition` 为 Chromium 系支持最佳；Firefox/Safari 支持度各异，代码已做能力探测与温和降级。
