# 小6 UI · v4.2 Voice Presence Layer — 状态流说明

> 描述 Voice Orb 五态（IDLE / LISTENING / PROCESSING / SPEAKING / ERROR）的流转、触发源与数据流向。
> 核心纪律：**不新增任何前端事件**；所有状态均由既有能力驱动。

---

## 一、状态属性共存模型

`#aiCore` 同时携带两个独立属性：

- `data-state`：AI Core 八态（IDLE/WAITING/THINKING/PLANNING/EXECUTING/COMPLETED/ERROR/OFFLINE），由 `agent_state` SSE 经 `ai-core.js` 驱动。
- `data-voice`：Voice Orb 五态，由 `voice-presence.js` 驱动。

两者正交共存，共同构成「小6的生命反馈」。Voice Orb 状态**不覆盖** AI Core 八态（例如 LISTENING 时 `data-state` 仍可能是 IDLE）。

## 二、状态流转图

```
                        ┌──────────────────────────────────────────┐
                        │                IDLE（默认）               │
                        └──────────────────────────────────────────┘
                           ▲              │  click / Ctrl+Shift+U
                           │              │  / wakeword_detected SSE
                           │              ▼
                  ┌────────────────────────────────┐
                  │   LISTENING（小6在接你的声音）   │◀──── 活动态(active) 持续
                  │   声纹向外扩散 · 麦克风标记亮起    │     每段识别后回到此处
                  └────────────────────────────────┘
                           │  识别到一句话（final）
                           ▼
                  ┌────────────────────────────────┐
                  │  PROCESSING（声纹收束，在想）     │
                  │   V4Intent.setText(文本) 实时字幕 │
                  └────────────────────────────────┘
                           │  +650ms
                           ▼
                  ┌────────────────────────────────┐
                  │  commit → V4Intent.submit(文本)  │
                  │  → ZZIntentGateway → /api/agent/intent
                  └────────────────────────────────┘
                           │  voiceDispatchAt = now
                           ▼
                  ┌────────────────────────────────┐
                  │  SPEAKING（agent_state 推进时）  │
                  │  仅当 voiceDispatchAt 在窗口内    │
                  │  声纹加速 · 小6在回应            │
                  └────────────────────────────────┘
                           │  +2200ms（或后端无响应 +4000ms 兜底）
                           ▼
                    returnToRest() ──► active? LISTENING : IDLE
```

## 三、各态触发与数据来源

| 状态 | 进入触发 | 数据/信号来源（既有） | 离场 |
|---|---|---|---|
| `IDLE` | 初始；停止；降级归位 | — | 用户/唤醒词开启 |
| `LISTENING` | 点击 Orb / `Ctrl+Shift+U` / `wakeword_detected` SSE | 既有 SSE 事件 + 用户交互 | 识别到一句话 → PROCESSING；或用户停止 → IDLE |
| `PROCESSING` | 识别到 final 文本 | 后端 `/api/asr` 返回文本 或 浏览器 `SpeechRecognition` final | +650ms → 提交 → SPEAKING 窗口 |
| `SPEAKING` | `agent_state` ∈ {EXECUTING,PLANNING,THINKING,REFLECTING} 且 `voiceDispatchAt` 在 12s 内 | 既有 `agent_state` SSE（经 `V4Data.onAgentState`） | +2200ms → returnToRest |
| `ERROR` | 麦克风未授权 / 识别不可用 | `getUserMedia` reject / `SpeechRecognition` `not-allowed` | +2600ms → `stop()` → IDLE |

## 四、识别文字数据流（无第二聊天框）

```
音频（浏览器采集）
   ├─ 主路径：POST /api/asr?ext=.webm ──▶ 后端 asr.py ──▶ 文本
   └─ 降级：SpeechRecognition(zh-CN) ───────────────────▶ 文本
        │
        ▼
V4Intent.setText(过程文本)        → 流入既有 Intent Line 输入框（实时字幕）
        │（final）
        ▼
V4Intent.submit(最终文本)          → 既有 ZZIntentGateway.dispatch
        │
        ▼
POST /api/agent/intent            → 后端 Intent Gateway → Agent Runtime
```

- **过程文本**（`interim`）只显示在输入框，不提交，不闪烁。
- **最终文本**（每段一句）提交一次，与键入行为完全一致（复用同一 `submit`）。
- 连续监听（`active=true`）下逐句投出；关闭后归位 IDLE。

---

## 五、降级与边界

- **后端 ASR 不可用**（本沙箱 `GET /api/asr/status` → `enabled:false`）：自动降级浏览器原生 `SpeechRecognition`，Voice Orb 仍可用。
- **浏览器不支持语音**（`getUserMedia` 与 `SpeechRecognition` 皆无）：点击给出温和文案「这个浏览器还不支持语音，打段字也行」，不崩溃。
- **麦克风被拒**：进入 `ERROR` 态（红色声纹一次轻脉冲）+ 文案提示，2.6s 后归位。
- **安全上下文**：`getUserMedia` 需 `https://` 或 `localhost`；本地 `http://127.0.0.1:8121` 满足。
