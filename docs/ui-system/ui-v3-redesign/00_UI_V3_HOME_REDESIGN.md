# 小6 Personal AI OS · 首页重新设计（UI-v3 Clean Reconstruction）

> 阶段：**设计阶段（先不写代码）**。本文件为 v3 首页的重新设计蓝图，供 Review。
> 立场：**废弃现有 UI 结构继承**——不是 v2/P1 的增量优化，而是从第一性原理重画首页。
> 约束：旧代码仅作为**能力来源**（数据 / 状态机 / 发送逻辑），**禁止复制** `osShell` 布局、左侧导航、HUD、Galaxy 首页、Dashboard 结构、多 Panel 结构。

## 0. 设计前提与能力来源（旧代码只作能力来源）

v3 不继承任何 DOM 骨架，但以下既有资产是真实的、可复用的**能力**，设计据此落地而非凭空：

| 既有资产 | 类型 | v3 中作为 | 引用方式 |
|---|---|---|---|
| `avatar-state.js` 8 态色板（IDLE/WAITING/THINKING/PLANNING/EXECUTING/COMPLETED/ERROR/OFFLINE） | 状态机 | AI Core 状态色 + Intent 占位符切换的**唯一状态权威** | 只读其状态，不复制其 DOM |
| `/api/goals`、`/api/memories`、`/api/knowledge` | 真实数据 | Goal / Memory / Knowledge 三域展示的**唯一数据源** | GET 只读，零新增后端 |
| `command-dock.js` 的 `sendText` 发送逻辑 | 行为 | Intent 行"回车即说话"的**真实动作** | 复用其发送，不复制输入框结构 |
| `galaxy-state.js` 关系投影数据层（实体+边） | 数据 | World Model 的**图数据基础**（用 2D 信息图重渲，非 3D 星系） | 取数据，弃渲染 |
| `zz-events.js` 的 `agent_state` 事件 | 事件 | Intent 占位符随真实状态切换的**触发器** | 订阅既有事件，不新增契约 |

**六类禁止项（绝不出现）**：`osShell` 三栏布局 · 左侧/顶部导航条 · HUD（品牌+时钟+主题色板+工具栏）· Galaxy/太阳系首页 · Dashboard 多卡片栅格 · 多 Panel 并列结构。

## 1. 产品定位重新定义

### 1.1 我们从哪里来
- v1/v2 的小6首页是"一个 AI 展示页面 + 一个聊天软件 + 一个星系软件"三心智拼合。
- v2 把它收敛为"AI OS 首页"，但仍沿用了 `osShell` 三栏 + 左导航 + HUD + 多 Panel。

### 1.2 v3 重新定义
> **小6 = 你的本地个人 AI 副驾。**
> **首页 = 小6的「在场表面」（Presence Surface）——它此时是谁、在做什么、知道什么、等你说话。**

关键转变：

| 旧心智（废弃） | v3 心智 |
|---|---|
| 首页是一个"页面"，用户来"使用功能" | 首页是小6的"在场"，用户来"与小6相处" |
| AI 是页面里的一个组件/聊天框 | AI 是空间的中心与主体，空间围绕它存在 |
| 功能以菜单/面板罗列 | 能力以"小6知道的事"融入在场，不罗列 |
| 用户先找功能再操作 | 用户直接对小6说话，小6调度一切 |

**一句话定位（首屏可见）**：
> 小6 · 你的本地个人 AI 副驾
> （副标题一行：完全在你的设备上运行 · 隐私优先）

## 2. 第一屏信息架构

### 2.1 原则
- **一个空间，无页面跳转感**。首屏是"默认在场"，不是"主页"。
- 信息由内向外分三层（由强到弱），无 Panel、无栅格、无卡片堆叠：
  1. **核心层（最强）**：AI Core —— 小6化身 + 身份 + 状态。
  2. **语境层（中）**：小6正在处理的事（当前目标一句话）+ 它知道什么（记忆/知识微光）。
  3. **意图层（常驻）**：底部一条 Intent 输入行。
- 其余视图（目标全集 / 记忆全集 / 知识全集 / 世界模型）是**覆盖层/轻展层**，由意图或快捷键唤起，**不破坏首页统一空间**。

### 2.2 首屏元素清单（仅此，无更多）
```
            ┌─────────────────────────────────────┐
            │                                     │
            │            [ AI Core ]              │   ← 核心层：化身 + 小6 + 状态色
            │       正在处理：<当前目标一句话>       │   ← 语境层·行动
            │   已掌握：<知识域> · 记住了：<最近记忆>  │   ← 语境层·认知（淡）
            │                                     │
            │                                     │
            ├─────────────────────────────────────┤
            │  ⌘  对小6说点什么…                  │   ← 意图层：唯一输入框
            └─────────────────────────────────────┘
```
- **没有**左侧导航、**没有** HUD、**没有**顶部品牌条、**没有**多 Panel、**没有** Galaxy。
- 快捷键（⌘1–⌘4 / ⌘K）是"焦点切换"而非"页面跳转"，唤起的是覆盖层，不出现导航条。

### 2.3 5 秒 / 30 秒认知目标
- **5 秒**：知道"这是小6，它在（在线/思考/执行），它现在在帮我做 X"。
- **30 秒**：知道"我直接在底下那行对它说话就能让它做事；它能记住、能查知识、能推进目标"。

## 3. AI Core 交互模型

### 3.1 构成（不是装饰，是"小6本人"）
- **化身（Avatar）**：一个随状态变色的**光核**（同心圆/呼吸环），不用太阳系、不用卡通形象、不用玻璃球。状态色直接取自 `avatar-state.js` 8 态色板（IDLE 静青 / THINKING 靛 / EXECUTING 绿 / ERROR 珊瑚红）。
- **身份**：`小6`（主）+ 一行副标 `你的本地个人 AI 副驾`。
- **状态**：以光核颜色 + 微动效表达，不靠文字标签堆叠。
- **正在处理**：光核下方一行动态文字，来自真实当前 Goal（如"正在推进：总结当前项目状态 · 0%"）。
- **下一步建议**：语境层中一句基于真实数据的轻引导（如"你有个目标尚未开始，要现在做吗？"），点击即填入 Intent 行。

### 3.2 交互
- **点击光核**：原地展开一个轻量"关于小6"浮层（能力/状态/身份），**不离开首页、不跳页面**。
- **呼吸节奏随状态**：IDLE 慢呼吸；EXECUTING 活跃脉冲；ERROR 警示性微颤。动效 ≤ 400ms，统一缓动。
- **光核是心理锚点**：让用户每次睁眼都确认"小6在这里"。

## 4. Intent 入口设计（The Intent Line）

### 4.1 形态
- 首屏**全屏唯一输入框**，位于底部居中，宽度受限（≤ 720px），不占满屏——像 Raycast 命令窗，但更"对话化"。
- 单色细线 + 微光，左侧一个 ⌘/小6符号。

### 4.2 占位符随真实状态切换（复用 `agent_state` 事件 + 8 态，不新增契约）
| AI 状态 | 占位符文案 |
|---|---|
| IDLE | 告诉我你的目标 |
| THINKING | 正在理解你的意图… |
| EXECUTING | 正在执行任务… |
| ERROR | 需要你的确认 |

### 4.3 行为
- **回车 = 对小6说话**（复用 `command-dock.js` 的 `sendText` 真实发送逻辑）。
- 支持自然语言 / 指令 / 提问——它是"说话"，不是"搜索框"。
- **⌘K** 唤起（复用既有 command palette 能力）。
- 视觉层级：意图行 > 一切装饰；它是首屏唯一"可操作入口"。

## 5. Goal / Memory / Knowledge 展示方式

### 5.1 统一原则
三者不是"三个页面/三个面板"，而是**"小6知道的事"**，以"氛围信息"融入在场，而非并排罗列。

### 5.2 各自呈现
- **Goal（目标）**：
  - 首屏只显示**当前进行中的 1 个目标** → 光核下方"正在处理"一行（真实数据：`/api/goals?status=active`）。
  - 其余目标不堆首屏；通过 Intent 或快捷键唤起"目标全集"覆盖层查看。
- **Memory（记忆）**：
  - 不在首屏列卡片。以核心旁淡入淡出的微提示呈现："记住了：<最近一条记忆摘要>"（真实数据：`/api/memories` 最新一条）。
  - 或收进"关于小6"浮层 / 记忆全集覆盖层。
- **Knowledge（知识）**：
  - 首屏用**语义化摘要**而非纯数字（继承 v2 P1.5 方向）：
    - 反例：`Knowledge 46`
    - 正例：`已掌握你的项目架构与历史设计`（来自 `/api/knowledge` 的类别聚合，如 架构/设计/对话史）。
  - 领域名直接呈现，数字降为次要。

### 5.3 数据来源（零新增）
全部来自既有 GET 端点，由 UI Data Adapter 只读投影（沿用 v2 建立的 adapter 纪律：只读、不碰 AppState、不新增事件）。

## 6. World Model 替代 Galaxy 方案

### 6.1 为什么不是 Galaxy
- 太阳系隐喻与"你的世界"无关；真实天文模拟（Three.js + 4.7MB 贴图）与 AI 语义零关联（v2 审计已证）。
- Galaxy 是"宇宙风景"，不是"小6对你的世界的理解"。

### 6.2 World Model 是什么
> **World Model = 小6对"你的世界"的结构化认知视图**——节点是你关心的实体（项目 / 人 / 目标 / 知识域），边是它们的关系。

### 6.3 形态（轻量 2D 信息图，非 3D 星系）
- 用 **SVG/Canvas 2D 关系图**渲染（数据来自 `galaxy-state.js` 的关系投影，但重渲为信息图）。
- 节点可点：点目标 → 看它连到哪些知识/记忆；点知识域 → 看它支撑哪些目标。
- 信息密度高、可解释、可交互，资源占用远低于星系。

### 6.4 触发与位置
- **不在首屏**（首屏只保留 AI Core + Intent + 氛围信息）。
- 作为"焦点切换"之一（如 ⌘4 或意图唤起），以**覆盖层/侧展层**出现，不破坏首页统一空间。
- 这是"AI OS"区别于聊天机器人的关键能力证明：**让小6"看见"并让你看见它如何理解你的世界**。

## 7. 视觉设计语言

参考：**Apple 极简 · Linear 信息密度 · Raycast 效率 · Claude 自然交互**。

### 7.1 色彩
- 深色优先（本地、私密、沉浸）。背景近黑或深空蓝（非纯黑，更柔）。
- **单一强调色**，由 presence 状态驱动（继承 8 态色板），不引入多彩主题。
- 语义靠同色相明度区分，不靠颜色种类堆砌。

### 7.2 空间
- 大量留白（Apple）：首屏是"空旷中的一点光"——小6在中心，周围是呼吸空间。
- **中心辐射布局**，不用 grid 多栏、不用左导航、不用顶栏。

### 7.3 字体
- 系统无衬线为主；等宽用于数据/状态（Linear/Raycast 感）。
- 字号层级克制，不靠大标题轰炸。

### 7.4 动效
- 克制微动效：光核呼吸、状态色过渡、意图行微光。
- **禁用炫技**：无粒子爆炸、无 3D 旋转星系、无玻璃卡片堆叠。
- 动效 ≤ 400ms，缓动统一（沿用 `ui2.css` 既有的 `--dur-*` / `--ease-*` 令牌体系）。

### 7.5 组件原则（红线）
- **无玻璃卡片堆叠** · **无重边框阴影** · **无图标墙**。
- 信息用"行"与"微光"组织，不是"盒子"。
- 状态用颜色 + 轻量形状表达，不是标签阵列。

### 7.6 密度与效率
- 像 Raycast：输入即达，信息随语境出现。
- 像 Linear：密集但有序，一屏不挤。
- 像 Claude：对话自然，意图行是"说话"不是"填表"。
