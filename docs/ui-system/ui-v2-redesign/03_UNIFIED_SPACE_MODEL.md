# 03 · Unified Space Model

> Xiao6 UI v2.0 · Phase 3-A
> 核心命题：如何让五个焦点感觉像**一个**软件

---

## 1. 问题的本质

现状之所以"像三个软件拼在一起"，根因不在视觉，在**切换机制**：

```js
// index.html:1467–1475（现状）
function openChat()     { body.classList.add('chat-mode');
                          body.classList.remove('universe-mode'); }
function openUniverse() { body.classList.add('universe-mode'); }
```

三个顶层容器 `.os-shell` / `.app` / `#universeView` **互斥显隐**。这在本质上等价于 `router.push('/chat')` —— 整块画面被替换，用户感知到的就是**换了个软件**。

> **只要还有"整块 DOM 显隐替换"，做多少视觉统一都救不回来。**

---

## 2. 统一空间模型：一个 Stage，四层

### 2.1 核心隐喻

> 小6不是一叠页面，是**一个房间**。
> 切换焦点不是换房间，是**转过身去看房间的另一面**。

房间的墙、光线、AI 的存在感始终不变，变的只是**你正对着的那一面**。

### 2.2 分层结构

```
┌─────────────────────────────────────────────────────┐
│ L0 · Ambient Layer   氛围层                          │  ← 永不变化
│      呼吸感背景 · presence 光晕 · 不可交互             │     跨焦点连续
├─────────────────────────────────────────────────────┤
│ L1 · Presence Layer  在场层                          │  ← 永不消失
│      AI 核心 · 状态 · 主动开口                         │     位置随焦点缩放
├─────────────────────────────────────────────────────┤
│ L2 · Focus Layer     焦点层  ★唯一变化的层            │  ← 五面之一
│      NOW / DOING / KNOWN / SENSING / SELF           │     内容置换
├─────────────────────────────────────────────────────┤
│ L3 · Intent Layer    意图层                          │  ← 永不消失
│      意图行 · 就地回应 · 执行流                        │     全焦点常驻
└─────────────────────────────────────────────────────┘
       L4 · Transient Layer 瞬态层（浮层/确认/详情）
```

**关键纪律：L0 / L1 / L3 在焦点切换时 DOM 不重建、不显隐、不重挂载。**
只有 L2 的内容区发生置换。

这一条是"感觉只有一个小6"的**技术保证**，不是风格问题。

### 2.3 各层职责

| 层 | 职责 | 焦点切换时 | 现有可复用 |
|---|---|---|---|
| **L0 Ambient** | 环境氛围、presence 色温 | 仅色调随 AI 状态微变 | ⚠️ 现为太阳系，需替换 |
| **L1 Presence** | AI 在场证明、状态、主动发声 | **位置与尺寸变化，实体不变** | ✅ `consciousness-core.js` |
| **L2 Focus** | 五面内容 | 内容置换（交叉淡入 + 微位移） | 🆕 重建 |
| **L3 Intent** | 输入、就地回应、执行流 | 完全不变 | ✅ `command-dock.js` + `execution-channel.js` |
| **L4 Transient** | 确认卡、详情、设置 | 独立生命周期 | ♻️ `overlay-manager.js` 收口 |

## 3. Presence 的连续性（最重要的一条）

**AI 核心（◍）在五个焦点中是同一个物理实体，从不销毁重建。**

它通过**位置与尺寸**表达当前焦点：

| 焦点 | 核心位置 | 尺寸 | 语义 |
|---|---|---|---|
| NOW | 屏幕中央偏上 | **240px** | "我在这里，我是主角" |
| DOING | 左上角锚点 | 72px | "我在旁边干活" |
| KNOWN | 左上角锚点 | 72px | "我在旁边陪你翻" |
| SENSING | 左上角锚点 | 72px | "我在旁边盯着" |
| SELF | 屏幕中央 | **180px** | "在看我自己" |
| 执行中 | 当前焦点内锚点 | 96px + 强脉动 | "我正在动手" |

**实现要求**：同一个 DOM 节点 + `transform` 过渡。**禁止**为不同焦点创建不同的核心实例。

```
NOW                      DOING
                         ◍ ← 同一个节点，
      ◍                     240px → 72px
    (240px)                 center → top-left
                            transform 过渡 420ms
```

> 用户视线全程能追踪核心的移动 —— 这在心理上确认了"AI 没变，只是我换了个角度看它"。
> **这一个设计，胜过任何视觉统一规范。**

## 4. 焦点转移机制

### 4.1 三条纪律

1. **不卸载**：L2 内容用 `visibility` + `opacity` + `transform` 切换，DOM 保留（除非内存压力）。
2. **不重置**：离开焦点时保留滚动位置、展开状态、筛选条件。回来时**回到你离开的地方**。
3. **不打断**：焦点切换绝不中断正在执行的任务。执行流在 L3 持续可见。

### 4.2 转移动效规范

```
焦点切换（⌘1–⌘5 或点击脊柱）：

  L0 Ambient   ── 色温平移 600ms ease-premium
  L1 Presence  ── transform 420ms cubic-bezier(0.16,1,0.3,1)
  L2 出场      ── opacity 1→0 (140ms) + translateY 0→-8px
  L2 入场      ── opacity 0→1 (220ms, delay 100ms) + translateY 12px→0
  L3 Intent    ── 无变化（关键）
```

**总时长 ≤ 420ms**，重叠执行。

**禁止**：横向滑动切换（那是标签页心智）、翻页动画、缩放整屏（那是页面跳转心智）。

### 4.3 焦点状态机

```
              ┌─────────────────────────────┐
              │        NOW（默认）           │
              └──┬───────┬───────┬───────┬──┘
        ⌘2 / 点击│  ⌘3   │  ⌘4   │  ⌘5   │
                 ↓       ↓       ↓       ↓
              DOING   KNOWN  SENSING   SELF
                 │       │       │       │
                 └───────┴───┬───┴───────┘
                             │ Esc / ⌘1
                             ↓
                            NOW
```

**规则：**
- `Esc` 在任何焦点 → 回 NOW（浮层优先：有 L4 浮层时先关浮层）
- 焦点之间**可直接跳转**，无需回 NOW 中转
- 无历史栈、无前进后退 —— **这不是浏览器**
- URL 不参与状态（本地应用，无路由概念）

## 5. 意图层的就地展开

这是"零页面跳转"的核心机制。用户说的话，**在他所在的地方**得到回应。

```
┌─────────────────────────────────────────────┐
│  L2 · 当前焦点内容（例如 KNOWN 记忆列表）      │
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │ ◈ 就地回应区（Inline Response）        │  │  ← 从意图行上方生长
│  │   AI 理解 / 确认卡 / 执行流 / 结果卡    │  │     不遮挡、不弹窗
│  │                    [ 就这样 ] [ 改一下 ]│  │     可折叠为一行
│  └───────────────────────────────────────┘  │
├─────────────────────────────────────────────┤
│  ▸ 帮我盯一下竞品定价…                  ⌘K  │
└─────────────────────────────────────────────┘
```

**四种就地回应形态：**

| 形态 | 场景 | 生命周期 |
|---|---|---|
| **理解卡** | AI 解析意图，请求确认 | 用户确认/修改后消失 |
| **执行流** | 步骤级实时进度 | 执行结束后折叠为结果 |
| **结果卡** | 数据、对比、答案 | 常驻至下一次输入，可 Pin |
| **回话** | 纯对话回复 | 追加进当前焦点的对话流 |

**跨焦点副作用可见**：在 KNOWN 焦点下创建了一个目标 → 不跳转，脊柱上「在做」出现 `+1` 徽标脉动一次。**用户知道发生了什么，但不被搬走。**

## 6. 浮层治理（L4）

现状 11 个顶层浮层容器，各自为政。v2 收敛为**三类，一套生命周期**。

| 类 | 用途 | 尺寸 | 关闭 | 可叠加 |
|---|---|---|---|---|
| **Sheet** | 详情展开（一条记忆、一个目标） | 右侧 480px | Esc / 点外 | 否 |
| **Dialog** | 需要决断（授权、删除、确认） | 居中 440px | 仅按钮 | 是（最多 2） |
| **Toast** | 即时反馈 | 右下角 | 自动 3s | 是（堆叠 3） |

**被废除的浮层形态**：全屏模态（`mem-panel` 四栏 Obsidian 面板）、并列侧抽屉（settings/sysprompt/cap 三套独立结构）、右侧常驻遥测栏。

**统一治理**：全部经 `overlay-manager.js` 单栈管理，Esc 逐层弹出，z-index 只用 token 阶梯。这一点现状已有良好基础，v2 强化为**唯一通道**。

## 7. 响应式：删掉 scale 骗局

**现状（index.html:1546–1557）必须删除：**

```js
const baseW = 1920, baseH = 1080;
const scale = Math.min(innerWidth / baseW, innerHeight / baseH);
app.style.transform = 'scale(' + scale + ')';
```

固定 1920×1080 画布整体缩放 —— 小窗口下文字全糊、点击热区偏移、DPI 适配失效。**这是伪响应式。**

**v2 断点策略：**

| 宽度 | 脊柱 | L1 核心 | L2 布局 | L3 意图行 |
|---|---|---|---|---|
| ≥ 1600 | 图标 + 文字 | 全尺寸 | 双栏 | 居中 720px |
| 1200–1600 | 图标 + 文字 | 全尺寸 | 单栏宽 | 居中 640px |
| 900–1200 | 仅图标 | 缩至 0.8 | 单栏 | 全宽 - 48 |
| < 900 | 底部横向 | 缩至 0.6 | 单栏紧凑 | 全宽 - 24 |

真实 CSS Grid + clamp()，无 transform scale。

## 8. 状态归属表（防止再次失控）

每一类状态**只有一个归属**，杜绝多处真相。

| 状态 | 唯一归属 | 消费方 |
|---|---|---|
| 当前焦点 | `body[data-focus]`（新增，唯一新状态） | 脊柱高亮、L2 显示、L1 位置 |
| AI 在场态 | `body[data-presence]`（已有） | L0 色温、L1 动效、脊柱脉动 |
| 主题 | `body[data-theme]`（已有） | 全局 token |
| 领域数据 | `AppState`（已有） | 全部 L2 内容 |
| 执行进度 | `ExecutionChannel`（已有） | L3 执行流 |
| 浮层栈 | `OverlayManager`（已有） | L4 |

> **v2 只新增一个状态：`data-focus`。**
> 五个 body 模式类（chat-mode / universe-mode / cp-mode / os-context-open …）全部废除，
> 由这一个属性取代。这是 IA 简化在代码层的直接体现。
