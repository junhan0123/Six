# 05 · GALAXY 角色重新定义（Phase 4）

> **阶段纪律**：本文件属于 `ONLY DESIGN` 阶段。本文只做产品决策与设计规格，**不修改任何代码 / CSS / HTML / JS / 后端 / Agent Runtime，不提交 Git**。任何移除 / 重写动作均标注为"待实施"（见 `07_IMPLEMENTATION_ROADMAP.md`）。

---

## 0 · 一句话结论（先给答案）

**当前 Galaxy（3D 太阳系"AI World Map"）作为首屏目的地 → 完全移除（对应选项 C）。**

**但承载它的关系投影数据层（`galaxy-state.js`）→ 保留、降级、重生（对应选项 B 的精神）。**

最终推荐不是三选一的单选题，而是一次"**拆骨留肉**"：

| 组成 | 处置 | 映射选项 |
|---|---|---|
| `solar-system.js` 天文渲染 + 4.7MB 贴图 + Three.js 1.27MB | **删除** | C 完全移除 |
| `galaxy-runtime.js` / `galaxy-experience.js` 交互包装层 | **随渲染层一起删除** | C 完全移除 |
| `#universeView` 作为一级导航 `galaxy` 入口 | **从一级导航移除** | C 完全移除 |
| `galaxy-state.js` 关系投影（goal/agent/task/memory/knowledge → 节点图） | **保留并升级** | B 弱化（降级为 KNOWN 的"关系"子视图） |

> 即：**天文形态走 C，关系资产走 B。** 两者不能混为一谈——这是上一轮五代 CSS 叠加都没治好的根因：把"Galaxy 没价值"和"Galaxy 数据有价值"当成一句话，结果每次都只敢把天文调暗、从不敢动结构。

## 1 · Galaxy 到底解决什么问题？（设计原意的诚实还原）

要决定去留，先还原它**被造出来的初衷**，而不是它**现在长成的样子**。

从代码与目录命名看，Galaxy 的原始命题是一个有野心、且合理的命题：

> **让 AI 的"内部世界"可见** —— 把抽象的目标、智能体、任务、记忆、知识，投影成一张可浏览的关系网络。用户不看日志、不读结构，一眼就能理解"小6脑子里现在有什么、它们之间怎么连"。

这是一个 **AI 自我可视化（AI self-visualization）** 命题，不是"做个好看的天文背景"。它想解决的真实问题是：

1. **可解释性焦虑**：用户把权限交给一个黑盒，天然想知道"你到底在想什么、在管什么"。
2. **全局感**：目标驱动系统里，goal/agent/task 是动态变化的，文字列表看不出"当前拓扑"。
3. **关系发现**：记忆和某条知识相关、某条知识和某个目标相关——这类隐性连接，列表视图永远暴露不出来。

**命题本身是对的。错的是实现把命题偷换成了"天文模拟器"。**

---

## 2 · 现状解剖：三层剥离（为什么实现背离了命题）

审计 `xiao6-ui/` 下 Galaxy 相关文件，它实际由三层组成，价值天差地别：

### 2.1 渲染层 · `solar-system.js`（29KB + ~6MB 资源）—— ❌ 噪音源
- **真实 NASA 行星贴图**（地球/火星/木星等）+ **真实轴向倾角 / 自转 / 公转周期**（海王星 164.8 年）。
- 这是一台**物理正确的太阳系模拟器**，与 AI 语义 **零关联**。
- AI 语义映射被硬塞进同一画布：
  ```js
  // solar-system.js 576-580
  collect(model.planets,  'goal');      // 目标
  collect(model.satellites,'agent');    // 智能体
  collect(model.orbits,   'task');      // 任务
  collect(model.archives, 'memory');    // 记忆
  collect(model.links,    'knowledge'); // 知识
  ```
  结果：真实行星占据半径 13–98 的**中心舞台**，而 AI 语义节点被渲染成 `0x88aaff` 灰蓝小球，推到 `radius 115+` 的**外围冷宫**。
- 视觉预算 100% 给了天文，0% 给了智能（见 `00` §2 Q5）。

### 2.2 数据层 · `galaxy-state.js`（AppState → 节点图）—— ✅ 真资产
- 把 `AppState` 中的 goal / agent / task / memory / knowledge 投影为带关系的图。
- 这是**纯数据投影**，不依赖 Three.js、不依赖贴图、不依赖天文隐喻。
- 它回答的正是 2 节提出的真实问题：当前 AI 内部世界有什么、怎么连。
- **这一层才是 Galaxy 命题的本体。** 渲染层只是它的一个不幸的皮。

### 2.3 包装层 · `galaxy-runtime.js` / `galaxy-experience.js` —— ⚠️ 随渲染层重写
- 围绕 3D 画布的交互（拖拽、缩放、点击行星弹信息）。
- 这些交互体验绑定在"天文"隐喻上，一旦渲染层移除，包装层失去意义。

**结论**：Galaxy 的"价值"100% 在数据层，"成本与认知噪音"100% 在渲染层。去留决策必须按层切，不能整锅端也不能整锅留。

## 3 · 如果用户每天不用，为什么存在？（最难的问题，必须正面答）

Prompt 逼问一句：**"如果用户每天不用：为什么存在？"** 这一问直接戳破"它很酷所以留着"的幻觉。

### 3.1 诚实数据
- Galaxy 当前是 6 个一级导航之一（`home/workspace/command/galaxy/assistant/settings`），但：
  - 它是**静态展示**，不参与 Daily AI Workflow（晨/午/晚/夜闭环都绕开它）。
  - 用户打开它的动机极低：AI 语义节点在 115+ 外围，点不到、看不清、无反馈。
  - 主动引擎（`pending_proactive`，514 行）已停摆 6 天，`galaxy` 没有任何"活"的信号来吸引回访。
- **也就是说：它现在是一个"建好了但没人去的展馆"。**

### 3.2 "为什么存在"的三种可能答案（逐条检验）

| 假设 | 检验 | 结论 |
|---|---|---|
| A. 它是核心体验，用户天天用 | 与 3.1 事实相悖 | ❌ 不成立 |
| B. 它是"高级用户的深度工具"，低频但高价值 | 关系投影（数据层）确实对**想理解 AI 全局**的用户高价值 | ✅ 部分成立 → 应降级为低频深度视图，而非首屏 |
| C. 它只是"技术炫技 / 早期 demo 残留" | 渲染层是真实天文模拟器、与产品零关联，符合"demo 残留"特征 | ✅ 成立 → 渲染层应移除 |

**正面回答**：Galaxy 现在存在的唯一真实理由，是"数据层有潜在价值" + "渲染层是历史 demo 残留"。前者值得保留为**低频深度视图**，后者不值得占用任何首屏预算。**因此：让用户"每天不用"的那部分（天文首屏）就该移除；让用户"偶尔想用"的那部分（关系图）就该保留但降级。**

这正是"拆骨留肉"的决策依据。

## 4 · 三个设计选项完整展开

### 选项 A · 保留 Galaxy 定位为 "AI World Map"（作为旗舰目的地）

**主张**：把它当小6的"主世界"，AI 内部宇宙可视化就是产品门面。

| 维度 | 评估 |
|---|---|
| 认知 | ❌ 与"AI 是中心、首屏只见 AI"原则直接冲突——首屏变成天文，AI 退到 115+ 外围 |
| 价值密度 | ❌ 用户第一眼得到"太阳系真好看"，得不到"小6现在在帮我什么" |
| 资源 | ❌ 6MB 资源 + Three.js，为"酷"付费，不为"用"付费 |
| 频率 | ❌ 非 Daily Workflow 必经，强行当门面只会制造"三软件拼接"的第三个心智 |
| 与 v2 原则 | ❌ 违反"禁止 Galaxy 独立软件""Galaxy 不是主页" |

**结论**：A 直接否决。它正是当前问题的根源形态。

---

### 选项 B · 弱化 Galaxy 作为隐藏能力

**主张**：承认它低频高价值，移出一级导航，藏到次级入口（如 KNOWN 焦点下的"关系"视图）。

| 维度 | 评估 |
|---|---|
| 认知 | ✅ 不再与首屏竞争，用户第一眼只见 AI |
| 价值密度 | ✅ 想看关系的人能找到；不想看的人不被打扰 |
| 资源 | ✅ 只保留 `galaxy-state.js` 数据层（轻量、无 Three.js），砍掉 6MB 渲染 |
| 频率 | ✅ 低频场景（"帮我看看小6现在在管什么 / 这条记忆连到哪个目标"）有去处 |
| 与 v2 原则 | ✅ 完全符合"Galaxy 不是主页""功能入口简单" |

**代价**：关系图需要一个新的轻量渲染（力导向图 / 网络图，无需 3D），这是 B 唯一的实施成本——但远小于维护一套天文模拟器。

**结论**：B 是唯一既保住真资产、又不污染首屏的路径。

---

### 选项 C · 完全移除

**主张**：Galaxy 整体删除，关系数据也一并废掉。

| 维度 | 评估 |
|---|---|
| 认知 | ✅ 最干净，彻底消灭第三个心智 |
| 价值密度 | ❌ **误杀真资产**——`galaxy-state.js` 的关系投影是 v2 暴露"AI 内部世界"的唯一现成数据层 |
| 资源 | ✅ 省 6MB |
| 频率 | ❌ 想理解 AI 全局的用户失去唯一入口 |
| 与 v2 原则 | ⚠️ 干净但浪费——v2 的 KNOWN"关系"视图将不得不从零重建数据层 |

**结论**：C 对"天文形态"完全正确，对"数据层"是倒脏水连孩子一起倒。

## 5 · 最终推荐（明确、可执行）

**采用"混合裁决"，并落到 A/B/C 语言：**

> **天文渲染层（solar-system.js + 贴图 + Three.js + runtime/experience 包装层 + 一级导航入口）= 选 C，完全移除。**
>
> **关系投影数据层（galaxy-state.js）= 选 B，弱化重生：作为 KNOWN（记得）焦点下的第 3 个视图「关系」，与「记忆 / 知识 / 对话」并列。**

### 5.1 为什么不是纯 C、也不是纯 B
- 纯 C 会逼着 v2 在 KNOWN 里从零造一个关系图——而 `galaxy-state.js` 已经把 AppState 投影成节点图的活干完了，纯 C 是浪费。
- 纯 B（保留天文为首屏 / 保留一级导航）会把"三软件拼接"的第三个心智原封不动留给用户，v2 前功尽弃。
- 混合裁决 = 把 C 的"斩首"（去首屏、去导航、去天文）和 B 的"留肉"（保数据、降级视图）结合，恰好是"拆骨留肉"。

### 5.2 重生的「关系」视图长什么样（落到 04 规格）
见 `04_SCREEN_SYSTEM_V2.md` Screen 3 · 记得 KNOWN 的视图矩阵：

| 视图 | 内容 | 数据源 | 状态 |
|---|---|---|---|
| 记忆 | 34 条，时间倒序 | `memories` 表 | ✅ 复用 memory.js |
| 知识 | 46 篇 md，目录树 | `knowledge/` | 🆕 首次暴露 |
| **关系** | **记忆↔知识↔目标 拓扑图** | **`galaxy-state.js` 投影 + manifest 35 关系** | **♻️ Galaxy 重生** |
| 对话 | 历史会话 | `chat_log` | ♻️ 从独立软件降级 |

重生的「关系」视图规格：
- **渲染**：用二维力导向网络图（SVG / Canvas，无 3D、无贴图），节点=goal/agent/task/memory/knowledge，边=`galaxy-state.js` 已算好的关系。
- **交互**：点击节点 → 侧栏展开该实体详情 + 跳转对应 KNOWN 子视图（记忆/知识/目标）。
- **默认态**：收起为 KNOWN 的一个 tab，不自动播放、不占用首屏一像素。
- **诚实标注**：如果某类关系当前数据为空（如主动引擎停摆导致 task 边稀疏），视图显示"暂无活跃连接"，**不伪造热闹**。

### 5.3 验收对照（取自 `00` 最终验收清单）
| 验收项 | 本决策是否满足 |
|---|---|
| 用户感觉只有一个小6 | ✅ Galaxy 不再是独立心智 |
| Galaxy 不是主页 | ✅ 降为 KNOWN 子视图 |
| 首屏高级、科技感强 | ✅ 6MB 天文噪音移除，首屏只留 AI 核心 |
| 功能入口简单 | ✅ 一级导航从 6 项减到 Focus Spine 5 焦点 |
