# 04 · Screen System v2.0

> Xiao6 UI v2.0 · Phase 3-B
> 依据：`03_UNIFIED_SPACE_MODEL.md`
> **重要：以下五个"Screen"不是五个页面，是同一空间的五种注意力状态（L2 内容置换）。**

基准分辨率 1600×1000。全部尺寸为设计值，实现用 token + clamp()。

### 元素规格

| 元素 | 规格 | 数据源 |
|---|---|---|
| Presence Core | 240px canvas，呼吸周期 4s，色 = `--presence-color` | `AvatarState.deriveFromGlobals()` |
| 状态字 | 12px，`--text-dim`，字距 0.08em | 同上 |
| 主动开口 | 22px/1.6，最多 2 行，`--text` | `proactive.py` + `learnings` |
| 行动按钮 | 仅当 AI 提出具体建议时出现，最多 2 个 | 洞察 payload |
| 态势卡 ×3 | 高 88px，仅数字 + 一行摘要 | goals+tasks / memories / pending_proactive |

### 硬性约束

- **元素总数 ≤ 6**。这是全系统信息密度最低处。
- **主动开口不得为空**。无洞察时，退化为对昨日的陈述（"昨天没什么异常"），**绝不显示 placeholder 或产品文案**。
- 态势卡数字为 0 时**整卡变暗但不隐藏**——数字是承诺，消失是失信。
- 无任务时核心静止呼吸；有任务时脉动加快。

### 状态变体

| AI 状态 | 核心 | 主动开口区 |
|---|---|---|
| IDLE | 慢呼吸，青 | 今日摘要 |
| THINKING | 中频脉动，青亮 | "正在理解…" |
| EXECUTING | 快脉动 + 环形进度，橙 | 就地展开执行流 |
| WAITING | 静止 + 边缘闪烁，黄 | 待确认卡片 |
| ERROR | 静止，红（**不脉动**——错误不制造焦虑） | 错误说明 + 建议 |

### 关键设计

**1. 目标即容器，任务是它的展开**
不做两个列表。一个目标卡内联显示其子任务（`tasks.goal_id` 软外键已支持），进度由子任务完成比例自动聚合（`goals.py` 已实现）。

**2. 不存在"新建目标"按钮**
用户在意图行说话 → `goal_decision_engine.py` 解析 → 理解卡确认 → 落库。
**表单是上个时代的产物。这是 AI OS。**

**3. 执行步骤实时流式**
`◐ 执行中…` 的行随 `ExecutionChannel` 的 `tool_start` / `tool_end` 事件更新。这是"AI 真的在干活"最强的证据，必须在此可见。

**4. 授权就地发生**
`policy_engine.py` 的四级授权（auto/confirm/session/never）在此展示。**不弹模态框**——弹窗打断心流，就地卡片让用户在上下文中决断。

### 必需的后端补充（v2 唯一后端改动）

`server.py` 当前**从不 import goals**，需新增：

```
GET    /api/goals            列表（含子任务聚合进度）
POST   /api/goals            创建
PATCH  /api/goals/{id}       更新（状态/进度/标题）
DELETE /api/goals/{id}       删除
POST   /api/goals/{id}/plan  调用 plan_goal 拆解
```

**纪律：只做 HTTP 暴露，不改 `goals.py` 任何业务逻辑。**

### 空状态

```
              ◍
     还没有在做的事。

     试试说：「每天早上帮我看一眼行业新闻」
              「这周把 Q3 复盘写完」
```

**空状态给例句，不给按钮。** 教会用户说话，而不是教会他点击。

### 四个视图

| 视图 | 内容 | 数据源 | 状态 |
|---|---|---|---|
| **记忆** | 34 条，按时间倒序 | `memories` 表 | ✅ 复用 memory.js |

### 关键设计

**1. 三栏变两栏**
废除现有 `mem-panel` 的 Obsidian 四栏（文件树 + 标签 + 主区 + 大纲/反链）。**这是笔记软件心智，不是 AI OS 心智。** v2 用「列表 + 详情」两栏，大纲与反链收进详情底部的「相关」区。

**2. "相关"是 AI 织出来的**
详情底部展示跨类型关联（记忆→目标→知识）。这是小6区别于笔记软件的关键：**关联不是用户手动 `[[链接]]` 的，是 AI 自动织的。**

**3. 记忆不可直接编辑**
记忆是 AI 的认知产物，用户可以「纠正」（说一句话让 AI 改）但不直接改数据库。知识文档可编辑（它们是用户的资产）。
