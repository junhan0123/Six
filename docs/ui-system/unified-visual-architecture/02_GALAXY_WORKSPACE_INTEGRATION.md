# 02 · Galaxy 与 Workspace 融合方案（Galaxy–Workspace Integration）

> **文档类型**：统一视觉架构设计 · 核心融合决策

> **上游依据**：`00_DESIGN_PRINCIPLES.md` · `GALAXY_INTERACTION_SPEC.md`（DECISION_004）· `DOMAIN_MODEL.md` · `DESIGN.md` §1/§6

---

## 0. 问题陈述

当前最大割裂感来自：**银河（Galaxy）被当作「背景图」，Workspace 是「另一个界面」**，二者视觉语法不同、互不说话。用户的核心抱怨「太阳系与主界面割裂」正源于此。

本章必须在 **DECISION_004 的硬边界内**解决这一割裂：
- 银河 = 表现层 + 受控交互层；
- **不得持有可写状态**；**不得修改 `solar-system.js` 本体**；
- 所有交互经 `galaxy-overlay` 叠加层；Overlay Runtime 与 Galaxy 渲染解耦。

> 任何「让银河直接承载业务状态 / 改写本体」的方案，一律否决（违反 L0 红线-5 + DECISION_004）。

## 2. 四个候选方案比较

### 方案 A · Galaxy 作为主空间（Galaxy-Dominant）
- **形态**：银河占据主视图中央；Workspace 面板以悬浮卡片漂浮于银河之上，银河是「家」。
- **优点**：银河存在感最强，世界观最浓。
- **缺点**：① 操作面板会遮挡/干扰银河的精密可视化；② 高密度工作（Tasks/Execution）与银河「抢中央」，长期体验拥挤；③ 易诱发「让面板贴附星球」的越界冲动（触碰 DECISION_004 边界）。
- **边界风险**：🔴 高（中央区争夺 → 诱导改本体）。

### 方案 B · Workspace 嵌入银河（Embedded-in-3D）
- **形态**：面板定位在 3D 银河空间中（星球旁 / 轨道间）。
- **优点**：极致沉浸，「一个空间」感最强。
- **缺点**：① 要求 Galaxy 渲染 UI（违反 DECISION_004「不改本体 / 不持状态」）；② 破坏既有 2D 玻璃拟态设计系统（DESIGN.md）；③ 技术债与可访问性代价极高；④ 与「前端只读投影」架构冲突。
- **边界风险**：🔴 极高（直接违反 DECISION_004）。

### 方案 C · 双层空间模型（Dual-Layer Spatial，Galaxy=世界层 / Workspace=操作层）⭐ 推荐
- **形态**：银河作为**常驻世界层**（z 0–4，暗化但在场）；Workspace 作为**前景操作层**（玻璃元件，z 18+）。二者**共享同一空间语法**（depth / glass / grid / glow / motion），由**注意力模型**调节银河的显隐与提亮，而非硬切模式。
- **连通机制**（符合 DECISION_004）：
  - 点击行星 → 经 `galaxy-overlay` 展开该能力域面板（允许交互）；
  - 拖轨道 → 经 overlay 调 Goal（不改本体）；
  - 工具调用 → 光点沿轨道流转（可视化反馈）；
  - 「聚焦银河」手势（如空白处双击 / 专用控件）→ 世界层提亮、操作层半透明退后，进入「探索态」；再次操作 → 回到「操作态」。
- **优点**：① 彻底消除割裂——共享语法 + 始终在场 = 「一个 AI 空间」；② 完全满足 DECISION_004（银河纯可视化、零可写、不改本体、交互经 overlay）；③ 复用既有玻璃拟态系统，技术债低；④ 注意力模型比硬模式切换更连贯。
- **缺点**：需要精确控制银河的「暗化-提亮」节奏与前景面板对比，避免互相淹没（属实现细节，可在 Visual Redesign 调参）。
- **边界风险**：🟢 低（完全在 DECISION_004 内）。

### 方案 D · 动态切换双视图（Mode Toggle：Explore ↔ Operate）
- **形态**：顶栏/手势在「探索（Galaxy 全屏）」与「操作（Workspace 全屏）」间硬切换。
- **优点**：实现简单，两视图各自纯净。
- **缺点**：① 强化割裂——「两个模式」而非「一个空间」，与世界观目标相悖；② 用户需在两视图间反复跳转，打断流；③ 银河在「操作态」彻底消失 → 回到「背景图」老问题。
- **边界风险**：🟡 中（不违反边界，但违背世界观目标）。

## 4. 推荐方案：C · 双层空间模型（Dual-Layer Spatial）

### 4.1 核心定义
- **世界层（World Layer）= Galaxy**：`--z-ground`(0) → `--z-stage`(4)。始终渲染、暗化常驻。只投影 GalaxyState。
- **操作层（Operation Layer）= Workspace + Dock + Panels + AI Presence**：`--z-content`(18) 起。玻璃元件，共享语法。
- **注意力模型（Attention Model）**：不切换「界面」，只调节「世界层的可见强度」与「操作层的退后程度」。

### 4.2 两种注意力态（非硬模式，是连续调节）
| 态 | 触发 | 世界层 | 操作层 | 用途 |
|---|---|---|---|---|
| **操作态（Operate）** | 默认 / 输入焦点 / 面板展开 | 暗化（~30% 亮度，作为氛围） | 全亮、玻璃悬浮 | 日常工作、指令、执行 |
| **探索态（Explore）** | 聚焦银河手势 / 点击空白宇宙区 | 提亮（~80%，细节清晰） | 半透明退后（仍可交互） | 浏览状态世界、理解 AI 的「宇宙」 |

> 两态之间**连续缓动**（`--ease-premium`），无硬切闪烁。

### 4.3 银河 ↔ 工作区的桥（符合 DECISION_004 的交互）
| 交互 | 机制 | 是否改本体 |
|---|---|---|
| 点击行星（能力域） | `galaxy-overlay` 展开能力面板 | ❌ 不改 |
| 拖轨道（Goal） | overlay 调 Goal，银河仅视觉反馈 | ❌ 不改 |
| 工具调用光点 | 沿轨道流转的可视化 | ❌ 不改 |
| 流星（主动推送） | 经 SYSTEM 事件投影为视觉流星 | ❌ 不改 |

### 4.4 为什么 C 不违反任何红线
- 银河**零可写状态**：仍是 GalaxyState 只读投影。
- **不改 `solar-system.js` 本体**：暗化/提亮是前景遮罩或渲染参数调节（表现层），自转/公转/星空资产 100% 保留。
- **交互全经 `galaxy-overlay`**：Overlay Runtime 与 Galaxy 渲染解耦（DECISION_004）。
- **未新增 Runtime / Memory / EventBus**：注意力态是纯表现层状态，不入 AppState 子树。

## 5. 落地到 Visual Redesign 的设计要求（非实现）

1. 世界层与操作层**共用 depth ladder / glass / grid / glow / motion**（详见 `03`）。
2. 「探索态 / 操作态」的调节参数（亮度阈值、缓动时长）在 Visual Redesign 阶段以令牌形式落地（见 `06` 的 `--attention-*` 提议）。
3. 银河点击行星 → 能力面板，复用既有 `galaxy-overlay` + Panel 系统，不新建 overlay 管理器（DESIGN.md §4.7 单一管理器纪律）。
4. 默认态为「操作态」；银河暗化常驻，确保「割裂感」从根消除。
